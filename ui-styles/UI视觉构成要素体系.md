# UI 视觉构成要素体系

> 配套文档：`UI设计风格调研.md`（讲"有哪些风格"）、`index.html` + `pages/*.html`（讲"风格长什么样"）
> 本文讲第三件事：**网页的视觉到底由哪些东西构成**。把散落的术语归档到一个分层架构里，再逐层解释。
> 适用：毕设开题 / 论文第 2 章"相关技术综述" / 答辩时被问"你这套设计的依据是什么"

---

## 0. 先给结论：六层架构

网页给人的视觉感受，不是由某一个元素决定的，而是**六个层次自下而上叠加的结果**：

```
┌─────────────────────────────────────────────────────────┐
│  L5  感知层  Perception                                  │  ← 用户主观"感觉到的"
│      视觉重量 · 视觉层级 · 视觉动线 · 认知负荷 · 情绪基调  │     舒服 / 高级 / 拥挤 / 清晰
├─────────────────────────────────────────────────────────┤
│  L4  时间层  Motion                                      │  ← 视觉在时间上的表现
│      微交互 · 缓动曲线 · 时长 · 反馈 · 骨架屏 · 视差      │     跟手 / 顺滑 / 卡顿 / 廉价
├─────────────────────────────────────────────────────────┤
│  L3  表面层  Surface                                     │  ← 所谓的"风格"主要在动这一层
│      色彩 · 圆角 · 边框 · 阴影 · 透明度 · 模糊 · 渐变     │     拟物 / 扁平 / 玻璃 / 粗野
│      纹理 · 图标语言 · 插画语言                           │
├─────────────────────────────────────────────────────────┤
│  L2  骨架层  Layout                                      │  ← 决定"整不整齐"
│      网格 · 栅格 · 间距刻度 · 对齐 · 容器 · 断点 · 密度   │     规整 / 松散 / 有秩序感
├─────────────────────────────────────────────────────────┤
│  L1  原子层  Atom                                        │  ← 最小组成单元
│      字体 · 字号 · 字重 · 行高 · 字间距 · 图标 · 图像 · 控件│    字好不好看、细节到不到位
├─────────────────────────────────────────────────────────┤
│  L0  度量层  Measure                                     │  ← 物理与数学底座
│      视口 · 像素密度 · 单位 rem/px · 模数比例 · 基准网格   │     所有数值从哪来
└─────────────────────────────────────────────────────────┘
                        ⟂ 贯穿全部层
        Design Token 设计令牌 / Design System 设计系统（约束机制）
```

**三层读法**

1. **下层决定上层**：L0 的数值制度 → L1 的字号间距 → L2 的排布 → L3 的皮肤 → L4 的动作 → L5 的感受。
2. **风格只换 2 层**：所谓"换个风格"，几乎只改 **L3 表面层**（颜色/圆角/阴影/质感）和少量 **L4**（动效性格）。L0–L2 基本不动。
3. **所以 —— 风格 ≠ 好用。** 这也是为什么上一批四个演示页换了四套皮，界面照样能用：它们共享同一套 L0–L2 骨架。**好不好的上限由 L3/L4 决定，但下限由 L0–L2 保证。**

> 论文里可以这么写：「界面视觉质量可拆分为六个耦合层次，风格迁移主要作用于表面层与时间层，而可用性基线由度量层、原子层与骨架层共同决定。」

## L0 · 度量层 Measure — 所有数值从哪来

**层定位**：这一层不产生任何可见像素，但它决定了界面里每一个数字。绝大多数"说不清哪里不对"的界面，根因在这一层——数值是拍脑袋定的，没有比例关系。

| 术语 | 英文 | 定义 | 常用取值 / 坑点 |
|---|---|---|---|
| 视口 | viewport | 浏览器可见区域尺寸 | 移动端要写 `<meta name="viewport">`，否则按 980px 虚拟视口渲染，布局直接崩 |
| CSS 像素 / 物理像素 / DPR | px / device pixel / devicePixelRatio | CSS px 是逻辑单位，DPR=2 的屏上 1 CSS px 用 4 个物理像素渲染 | 1px 边框在高清屏上显虚 → 可用 `0.5px` 或 `border-image`；图片要 2x/3x 才不糊 |
| 相对单位 | rem / em / ch / vw / dvh | rem 相对根字号，em 相对父级，ch 相对字符宽度，dvh 解决移动端地址栏抖动 | **正文一律用 rem**，用户才能靠浏览器字号设置放大（WCAG 1.4.4 要求可放大到 200% 不破版） |
| pt / dp / sp | — | pt 印刷单位（1pt≈1.333px）；dp/sp 是 Android 的物理抽象单位 | 网页别用 pt，这是 PPT/AI 的体系 |
| 模数化比例 | Modular Scale | 从基准值按固定比率生成一串数字：12 / 14 / 16 / 20 / 25 / 31 / 39 | 常用比率：1.125（微调）· 1.200 小三度 · **1.250 大三度（最常用）** · 1.414 增四度 · 1.618 黄金比 |
| 基准网格 | 4pt / 8pt grid | 所有间距取 4 或 8 的整数倍：4 8 12 16 24 32 48 64 | 8pt 是 Material/iOS 共识；**偶数基准的好处是缩放/放大时不出现半像素毛边** |
| 布局栅格 | 12-column grid | 页面切 12 等份，元素跨若干份 | 12 能被 2/3/4/6 整除，排布最灵活；中国 APP 常用 24 栅格 |
| 容器 | container / max-width | 限制内容最大宽度 | 正文容器 640–760px；全屏流（如看板）可 1200–1440px 或不设上限 |
| 断点 | breakpoint | 布局切换的视口阈值 | 常见：≤640 手机 / 641–1024 平板 / >1024 桌面 |
| 流式数值 | clamp() / fluid | `clamp(最小值, 首选值, 最大值)` 让字号随视口线性变化 | 解决"手机上太大、桌面上太小"，一行替代多套断点 |
| 安全区 | safe-area-inset | 刘海屏/灵动岛不可覆盖区 | iOS 底部按钮必须 `padding-bottom: env(safe-area-inset-bottom)` |

## L1 · 原子层 Atom — 最小组成单元

**层定位**：字体、图标、图像、控件。这一层做不好，界面会显得"廉价"，哪怕布局很规整。

### 1.1 字体排版 Typography

| 术语 | 英文 | 定义 | 常用取值 / 坑点 |
|---|---|---|---|
| 字型 / 字体 | Typeface / Font | **字型**是设计（如思源黑体），**字体**是该设计的一个实例（思源黑体 Bold 24px）。日常混用，写论文要分开 | 写论文时别写"使用了黑体"，应写"字型：思源黑体；字重：Regular/Medium" |
| 字重 | weight | 笔画粗细，100–900 | 界面只用 3 档最稳：400 正文 / 500 强调 / 700 标题。**300 及以下的浅字重要配更高的对比度**，否则看不清 |
| 字号 | font-size / type scale | 按模数比例生成的一档档字号 | 桌面正文 **≥16px**；辅助文案不低于 14px；12px 是硬底线（不可用于正文） |
| 行高 | leading / line-height | 两行基线之间距离，通常写成字号的倍数 | 英文正文 1.4–1.6；**中文正文 1.5–1.8**（汉字方块字、无升部降部留白，需要更多呼吸）；标题可压到 1.1–1.25 |
| 字间距 | tracking / letter-spacing | 字符之间的统一间距 | 中文小字可适当放宽到 0.02–0.05em；**大标题尤其是西文大标题要收紧到负值**（-0.01 ~ -0.03em） |
| 字偶距 | kerning | 特定字符对之间的间距修正（VA、To 等） | 浏览器默认处理，只有做 Logo/巨号标题才需要手动干预 |
| x-height / 升部 / 降部 / 字怀 | x-height / ascender / descender / counter | 小写 x 的高度 / 上伸笔画 / 下伸笔画 / 闭合的内白空间 | x-height 大的字型（如 Inter、思源黑体）在同字号下"显得更大"，选字体时要看它而不是看字号 |
| 可变字体 | variable font | 一个文件内含连续可变的轴：字重 wght、字宽 wdth、倾斜 slnt、视觉字号 opsz | 一个文件替代 9 个静态字重，省请求；代价是首包体积偏大 |
| 中西文混排 | — | 中英/中数混排时的间距、标点、基线对齐问题 | 三点：①字体栈把西文字体写在前面，让英文优先命中西文字型 ②括号/顿号是全角字符 ③中文标点挤压需 `text-spacing-trim`（支持度有限） |
| 排版层级 | type hierarchy | 一套字号+字重+颜色的组合规则，让人 1 秒内分清主次 | 相邻层级字号比至少 **1.2×**，最好 1.25–1.5×；最大标题约正文的 2–3× |

**可直接抄的中文正文参数**
```
font-size: 16px;  line-height: 1.75;  letter-spacing: .01em;
容器宽度 640–760px（约 30–40 个汉字/行）
段间距 = 0.75em，约为行高的一半，视觉上成组而不散
```

### 1.2 图标 Icon

| 术语 | 定义 | 坑点 |
|---|---|---|
| 线性 / 填充 / 双色 / 断点式 | 描边型 / 实心型 / 两色型 / 线条断开型 | **同一套界面只能有 1 种**，混搭立刻显得业余 |
| 光学尺寸 16/20/24 | 不同尺寸应有不同细节密度，不是等比缩放 | 24px 的图标缩到 16px 会糊成一团，需要专门的简化版本 |
| 光学对齐 optical alignment | 视觉重心对齐而非数学外框对齐 | 三角形、播放键按几何居中会"偏左"，需手动微调 |

### 1.3 图像与控件

| 术语 | 定义 | 要点 |
|---|---|---|
| 长宽比 aspect-ratio | 16:9 / 4:3 / 1:1 / 3:4 | 卡片图必须锁比例，否则不同内容高度参差，grid 立刻乱 |
| object-fit | cover（裁切填满）/ contain（完整留白） | 头像/封面用 cover；商品图用 contain |
| 控件密度 density | comfortable / compact 两档 | 后台管理系统常用 compact（行高 32px），C 端用 comfortable（44px+） |
| 目标尺寸 target size | 可点击区域大小 | **WCAG 2.2 要求最小 24×24 CSS px**，触摸主操作建议 44×44（菲茨定律） |

## L2 · 骨架层 Layout — 决定"整不整齐"

**层定位**：这一层是新手和熟手差距最大的地方。改对了，界面会有"秩序感"；改错了，再好看的配色也救不回来。

| 术语 | 英文 | 定义 | 要点 |
|---|---|---|---|
| 网格 / 栅格 | grid / columns | 把画布切分并把元素落在线上 | 12 栅格；栏目之间要有统一 gutter（常取 16/20/24px） |
| 间距刻度 | spacing scale | 只用一个有限集合的间距值：4 8 12 16 24 32 48 64 | **界面糊，80% 是因为间距值太多**。约束到 6–8 个值，立刻变整齐 |
| 外边距 / 内边距 / 间隙 | margin / padding / gap | 元素外、元素内、兄弟元素之间 | 优先用 Flex/Grid 的 `gap`，少用 margin，避免外边距合并 |
| 基线网格 | baseline grid | 所有文本行都落在同一套不可见的水平线上 | 多栏排版时能保证左右两栏文字横向对齐，这是"杂志感"的来源 |
| 对齐 | alignment | 左/右/居中/两端对齐 | **正文左对齐，不要两端对齐**（中文两端齐会拉出参差的词间空隙）；数字列右对齐，便于比对位数 |
| 视觉层级 | hierarchy | 通过尺寸/字重/颜色/留白建立的主次关系 | 一个界面只允许 1 个最强点，否则视线无处落脚 |
| 留白 | whitespace / negative space | 元素之间刻意的空间 | 分两种：**宏观留白**（区块之间，营造呼吸）和**微观留白**（元素之间，建立从属） |
| 邻近律 | proximity（格式塔） | 靠近的东西被认为是一组 | **这是最廉价有效的分组手段**——比加分割线、加底色都好用 |
| 密度 | density | 单位面积内的信息量 | 看板类可高密；阅读类必须低密。高密的前提是间距刻度严格 |
| 流式 / 自适应 | fluid / adaptive / responsive | 连续缩放 / 按断点切换布局 / 二者结合 | 现代写法：`grid-template-columns: repeat(auto-fit, minmax(240px, 1fr))` 一行搞定自适应卡片墙 |
| 容器查询 | container query | 按父容器宽度而非视口宽度响应 | 组件级的响应式，2026 已可放心使用 |
| 常见布局范式 | — | 单栏随笔 / 双栏左右 / 圣杯 / **Bento Grid** / 瀑布流 masonry / 仪表盘 dashboard | Bento Grid（便当盒）是当前作品集与产品首页的首选 |

## L3 · 表面层 Surface — 风格真正发生的地方

**层定位**：上一批四个演示页之间的差异，98% 发生在这里。

### 3.1 色彩 Color

| 术语 | 定义 | 要点 |
|---|---|---|
| HSL / **OKLCH** | 色彩模型。OKLCH 是感知均匀的现代模型：L 明度、C 彩度、H 色相 | OKLCH 下同一 L 值的不同色相，视觉亮度一致 → 批量生成色板不会忽明忽暗。新项目建议直接用 OKLCH |
| 色板 palette / 色调色阶 tonal palette | 每个颜色按明度生成 10 级（50–900） | Material 3 用"色调 SoC"而非"主色+加深浅色"，避免了手动调黑/调白的脏色 |
| 语义色 semantic color | 按含义命名：primary / danger / success / warning / surface / on-surface | **不要按外观命名**（"那个红色"），要按用途命名 |
| 60-30-10 法则 | 主色 60% / 辅色 30% / 强调色 10% | 强调色占比超标，界面立刻"吵" |
| 深浅色模式 | light / dark theme | 深色不是把颜色反相：**深色模式下饱和度要降、要减少纯白纯黑**（用 #0B0B0B 而非 #000） |
| 对比度 contrast ratio | 亮度差，1:1 ~ 21:1 | **WCAG 2.2 AA：正文 4.5:1；大字（≥24px 或 ≥18.66px 粗体）3:1；UI 控件与图形 3:1。AAA：正文 7:1。** 第 3 章演示里的新拟态正是死在对比度上 |
| 颜色单独承载信息 | 仅用颜色区分含义，不叠加图形或文字 | 约 1/12 男性有色觉障碍。**颜色永远不能是唯一的含义载体**，必须叠加图标或文字 |

### 3.2 形状与质感 Shape & Material

| 术语 | 定义 | 要点 |
|---|---|---|
| 圆角刻度 radius scale | 一组有限的圆角值：4/8/12/16/full | 同一圆角在不同尺寸的控件上视觉效果不同：**大容器用大圆角，按钮略小于容器，标签更大** |
| 高度层级 elevation | 用阴影表达"离底面的高度"，Material 为 0–5 级 | 层级要有明确跳变，否则看不出谁浮在上面 |
| 阴影三要素 | offset（偏移）/ blur（模糊）/ spread（扩展） | **粗野主义**：blur=0。 **玻璃拟态**：大 blur。 **黏土拟态**：大 spread。三者就差在这一个数上 |
| 内阴影 / 内高光 | inset shadow | 顶部 1px 白色 inset = 材质的厚度感；底部深色 inset = 凹陷感 |
| 描边 vs 分隔线 | border vs divider | 需要"框起来"用 border，只需要"分开"用 divider（或干脆留白） |
| 透明度 / 模糊 | opacity / backdrop-filter | `backdrop-filter` 必须下层有内容才有意义 |
| 纹理 / 噪点 | texture / noise / grain | 大面积纯色加 2–4% 噪点，可消除"塑料感"、增加温度（对应今年"反完美主义"趋势） |
| 渐变 | gradient | 线性 / 径向 / 锥形 conic。**大面积渐变容易显脏，控制在 2–3 个邻近色相内** |

### 3.3 图形语言 Graphic Language

图标风格（线性/填充）、插画风格（扁平/2.5D/手绘/像素）、图表风格、Logo 用法 —— 这三个必须与 L3 的质感和 L1 的字体保持同一个"性格"。**这是很多学生作品崩的地方：界面是现代极简，插图是可爱卡通风。**

## L4 · 时间层 Motion — 视觉在时间上的表现

**层定位**：常被学生毕设忽略的一层，但它是"廉价感 vs 高级感"的分水岭。

| 术语 | 定义 | 常用取值 / 要点 |
|---|---|---|
| 过渡 transition | 状态之间的插值动画 | 只动 `transform` 和 `opacity`（走 GPU 合成层）；动 `width/height/top` 会触发重排，掉帧 |
| 缓动曲线 easing | 速度随时间的变化方式 | 界面默认 **`cubic-bezier(.2,0,0,1)`（快出慢入）**；入场用 ease-out、退场用 ease-in；线性 linear 只用于循环加载 |
| 时长 duration | 动画总时间 | **<100ms 感觉是瞬时的；100–300ms 是舒适的；>400ms 开始觉得迟钝。** 移动端还要更短 |
| 微交互 micro-interaction | 悬停 / 按下 / 释放 / 成功 / 失败的小反馈 | 按下要有"形变"（缩 0.96 / 下沉），这是"可点"的最强暗示 |
| 骨架屏 skeleton + shimmer | 加载时的灰块扫光 | 比转圈圈感知更短。2026 已经是 AI 类产品的标准动作 |
| 乐观 UI | optimistic UI | 先渲染成功结果，失败再回滚 | 代价是要做回滚路径，毕设里量力而行 |
| 视差 / 滚动驱动 | parallax / scroll-driven animation | 2026 可用纯 CSS `animation-timeline: view()` 实现，无需 JS |
| 减少动效 | `prefers-reduced-motion` | **必做**。前庭功能障碍用户会因动效眩晕 |

## L5 · 感知层 Perception — 用户主观感受到的

**层定位**：这一层不在代码里，在人脑里。它是 L0–L4 全部决策**合起来产生的结果**。答辩时如果被问"为什么这样设计"，答案都该落在这一层。

| 术语 | 定义 | 怎么调上层来实现它 |
|---|---|---|
| 视觉重量 visual weight | 元素吸引视线的强度 | 受**面积、饱和度、明度对比、阴影、留白、位置**六项影响。想强调：加大字号、加深颜色、给它周围更多留白（而不是加粗加边框） |
| 视觉层级 hierarchy | 主次秩序 | 一屏之内有且只有一个最强点；层级数控制在 3 级以内 |
| 视觉动线 / 浏览路径 | 眼球的移动轨迹 | **F 型**适合文字密集页；**Z 型**适合内容少的落地页；**古腾堡图**适合左右对称的首屏 |
| 群化 / 格式塔五律 | 邻近、相似、闭合、连续、图底 | 邻近 → 调 L2 间距；相似 → 调 L3 一致性；闭合 → 用边框/底色；图底 → 靠 L3 对比度 |
| 可读性 vs 易读性 | legibility vs readability | **可读性**＝单个字看不看得清 → 靠 L1 字号字重 + L3 对比度；**易读性**＝连续读累不累 → 靠 L2 行宽行距 |
| 认知负荷 cognitive load | 处理信息所需的脑力 | 选项越多越慢（**希克定律**）；短期记忆约 7±2 项（**米勒定律**）→ 导航不要超过 7 项 |
| 可供性 affordance | 东西"看起来怎么用" | 按钮要像按钮：有边界/有底色/有按下反馈。这是 L1 控件 + L3 质感 + L4 反馈的合成结果 |
| 情感基调 tone / 视觉温度 | 界面传递的情绪 | 圆角大+暖色+插画=亲切；直角+高对比+单一色=专业；噪点+手绘=人情味 |
| 一致性 consistency | 同类元素表现相同 | **雅各布定律**：用户带着其他产品的习惯来用你的产品，别违背通用惯例（汉堡菜单、返回在左上、蓝色链接） |

## ⟂ 贯穿层：设计令牌 Design Token

**什么是 Token**：把每一层的取值抽成命名变量，用法设计师管理平台管控，代码工程师只消费变量。

```
L3 原始值  Primitive   color.blue.600 = #185FA5      ← 不带任何含义
   ↓
L3 语义值  Semantic    color.brand.primary = blue.600  ← 表达"用途"
                       color.text.danger  = red.600
   ↓
组件值     Component   button.bg.default = brand.primary  ← 表达"用在哪"
                       button.bg.hover   = brand.700
```

**为什么要这么绕**：改主题时只改语义层（把 `brand.primary` 从蓝换成紫），全站几十个组件同步变化。演示页里四套风格共享同一套 HTML，本质上就是**同一批组件 Token 换了四套取值**。

写进论文的说法：「采用三层令牌体系实现视觉风格的可配置化，风格切换作用于语义层映射，不触及组件结构，从而保证信息架构与视觉呈现解耦。」

## 易混术语辨析表

写论文和答辩最容易用错的几组：

| 易混 | 区别 |
|---|---|
| 字型 Typeface vs 字体 Font | 字型是设计本身，字体是"某字型 + 某字重 + 某字号"的具体文件 |
| 行高 line-height vs 行距 leading | 网页 CSS 的 line-height 是倍数、作用在整行框；传统 leading 是两基线间距离。中文语境常混称，论文里建议写"行高（line-height）" |
| 字间距 letter-spacing vs 字偶距 kerning | 前者全局统一；后者是特定字符对的修正 |
| 网格 grid vs 栅格 column | 网格是二维的横纵结构；栅格通常指纵向的 12 等分栏 |
| 留白 whitespace vs 间距 spacing | 留白是设计意图（主动取舍）；间距是实现这个意图的数值 |
| 拟物 Skeuomorphism vs 新拟态 Neumorphism vs 黏土 Claymorphism | 拟物＝模仿真实物体的材质纹理；新拟态＝元素从同色底爬出来（双向柔阴影）；黏土＝大圆角 + 高扩散厚阴影 + 马卡龙色 |
| 扁平 Flat vs 极简 Minimalism | 扁平是**不用**立体效果（技术手段）；极简是**少放**元素（取舍立场）。可以既扁平又不极简 |
| 响应式 responsive vs 自适应 adaptive | 响应式＝一套布局连续缩放；自适应＝准备多套断点布局。现在通常混用统称 |
| 无障碍 accessibility vs 包容性 inclusive design | 无障碍＝让有障碍者能用（有明确标准 WCAG）；包容性＝覆盖更广的多样性人群（含神经多样性），范围更大 |

## 四个演示页分别动了哪些层

回看已经生成的四个静态页，可以清楚验证这套架构：

| 页面 | L1 字体 | L2 骨架 | L3 表面（主要差异） | L4 动效 | L5 结果感知 |
|---|---|---|---|---|---|
| Neo-Brutalism | 系统黑体 800 字重，巨号标题 | 12 栅格未变、8pt 间距 | 3px 黑描边 + blur=0 硬阴影 + 零圆角 + 高饱和平涂 | 按下位移 2–3px | 生猛、复古、可信、**天然高对比** |
| Glassmorphism | 系统黑体，常规字重 | 同上 | `backdrop-filter: blur(18px)` + 半透明白 + 1px 白描边 + inset 顶部高光 | 悬停透明度提升 | 通透、层级靠"浮起来"、需注意 GPU 与对比度 |
| AI-Native UI | 同上，加入意图链路 chips | 同上，但支持**按 Token 重排**（.low 折叠） | 低饱和 + 紫色渐变 hero + 1px 发丝描边 + 骨架屏 shimmer | 流式光标、shimmer、自适应切换 | 克制、"会思考"、状态透明 |
| Y2K Retro | 系统字体 + 大写宽字距微文案 | 同上 | 塑料外壳（垂直渐变 + inset 高光）+ chrome 金属渐变字 + 透视网格 + 星芒 | 按下位移 2px、光泽扫过 | 潮流、乐观、年轻化 |

**结论非常清楚**：L1/L2 四页基本一致，差异全部集中在 L3 表面层与少量 L4 —— 这正是"风格是可换的一层皮肤，骨架才是可用性的根本"这句话的实证。

## 写论文时的可用句式

- 「界面视觉质量可建模为六层耦合结构，其中度量层与骨架层构成可用性下限，表面层与时间层承载风格差异，感知层为最终的体验评价对象。」
- 「风格迁移只作用于表面层的视觉属性映射（颜色、圆角、阴影、材质），不改变信息架构，因此可在不损失可用性的前提下完成。」
- 「以统一尺度校准的 spacing scale（4pt 基准）与 type scale（1.25 模数比）统一数值决策，避免拍脑袋取值带来的视觉噪声。」
