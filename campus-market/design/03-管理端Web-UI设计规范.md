## 一、设计原则

| # | 原则 | 落地判据 |
|---|---|---|
| 1 | **查得到优先于好看** | 任何一屏，管理员找到目标信息的操作不超过 3 次点击 |
| 2 | **一屏 3–5 个图表是上限** | 超过之后阅读成本陡增。宁可分页签，不要堆 |
| 3 | **数字必须能扫读** | 所有数值列用等宽数字（`tabular-nums`）右对齐，千分位分隔 |
| 4 | **状态色语义唯一** | 待审核=橙、通过=绿、拒绝/异常=红、停用=灰。同一状态全端同色，禁止随页面变化 |
| 5 | **破坏性操作必须有摩擦** | 删除 / 封禁 / 强制下架 一律走二次确认 Modal，并写明影响范围 |

> **本端不追求视觉风格**。与用户端的差异是刻意的：用户端是"逛"的场景，管理端是"查"的场景，审美取向不同是合理的，写进论文时要讲清楚这一点。

### 2.2 Semantic（管理端映射）

```css
:root{
  /* 主色：蓝。工具型产品的通用语义，与用户端的暖色形成角色区分 */
  --brand:        #1677FF;
  --brand-hover:  #4096FF;
  --brand-bg:     #E6F0FF;
  --brand-border: #91CAFF;

  --bg:      #F0F2F5;   /* 页面底，比用户端略深，衬托白卡片 */
  --surface: #FFFFFF;
  --border:  #E5E7EB;
  --border-ctrl:#D9D9D9;
  --text-1:  #1F1F26;
  --text-2:  #5E5E68;
  --text-3:  #9A9AA4;

  /* 状态色（语义唯一，全端一致） */
  --st-pending:#FF8F1F;  /* 待审核 */
  --st-pass:   #0FA968;  /* 通过 / 正常 */
  --st-fail:   #E5484D;  /* 拒绝 / 异常 / 封禁 */
  --st-off:    #9A9AA4;  /* 停用 / 已下架 */

  /* 间距：4pt 基准 */
  --s-1:4px; --s-2:8px; --s-3:12px; --s-4:16px; --s-5:20px; --s-6:24px; --s-8:32px;

  /* 字阶：body=14px */
  --f-xs:12px;   /* 表格次要、脚注 */
  --f-sm:13px;   /* 表格正文 */
  --f-base:14px; /* 正文 */
  --f-md:16px;   /* 卡片标题 */
  --f-lg:20px;   /* KPI 数值 */
  --f-xl:30px;   /* 大数值（今日 GMV 等） */

  --r-sm:4px; --r-md:6px; --r-lg:8px;
  --sh-1:0 1px 2px rgba(20,20,30,.06);
  --sh-2:0 2px 8px rgba(20,20,30,.08);   /* 卡片默认就有极浅阴影 */

  /* 结构尺寸 */
  --sider-w:208px; --sider-w-collapsed:48px; --header-h:48px; --content-pad:24px;
  --chart-h:300px;
}
```

**字重**：400 / 500 / 600。KPI 数值用 600；表格正文 400；表头 500。
**数字**：全局 `font-variant-numeric: tabular-nums`，保证列对齐。

## 三、布局与栅格

```
┌─ Sider 208px（可折叠 48px）─┬─ Header 48px ──────────────┐
│ Logo                        │ 面包屑        右侧：搜索/通知/头像 │
│ 菜单组：                     ├────────────────────────────┤
│  数据看板                    │ 内容区 padding 24px         │
│  商品管理                    │ ┌ KPI 卡 ×4 ─────────────┐ │
│  用户管理                    │ │ 数值 + 同比/环比        │ │
│  订单管理                    │ └────────────────────────┘ │
│  审核队列   [角标数字]        │ ┌ 图表卡 ┐ ┌ 图表卡 ┐      │
│  内容管理                    │ │ 300px  │ │ 300px  │      │
│  系统设置                    │ └────────┘ └────────┘      │
│                             │ ┌ 明细表格 ─────────────┐  │
│ 底部：折叠按钮               │ │ 筛选栏 + 表格 + 分页   │  │
└─────────────────────────────┴────────────────────────────┘
```

| 区 | 规范 |
|---|---|
| Sider | 固定 208px，深底或浅底均可（本方案取**浅底白、选中项 `--brand-bg`**）；折叠后 48px 仅显示图标 |
| Header | 48px，白底 + 1px 下边；左侧面包屑，右侧搜索 / 通知 / 头像 |
| 内容区 | 最大宽度不锁（管理端需要铺满），内边距 24px，卡片间距 16px |
| 卡片 | 白底 + 1px `--border` + 圆角 8px + `--sh-2`；标题区 16px padding，与内容区之间 1px 分隔线 |
| 栅格 | 24 栏 Ant Design 栅格；图表卡跨 12 / 12 或 8 / 8 / 8 |

**断点**：管理端仅适配 ≥1280；1024–1279 时 Sider 自动折叠为 48px；<1024 提示"请使用桌面浏览器"。**不为管理端做移动端适配**（这是合理的取舍，写进论文）。

## 四、组件规范

### 4.1 KPI 卡

| 项 | 规范 |
|---|---|
| 尺寸 | 高度 108px，一行 4 个，间距 16px |
| 结构 | 标题（`--f-sm` `--text-2`）→ 数值（`--f-xl` 600 `tabular-nums`）→ 同比/环比（`--f-xs`） |
| 趋势 | 上升用红、下降用绿（**遵守中国股市惯例**）；前缀 ▲/▼ 符号，不靠颜色单独表意 |
| 单位 | 金额 `¥`，数量「件」「人」；超过 1 万显示「1.2 万」并在 title 里给精确值 |

### 4.2 图表卡

| 项 | 规范 |
|---|---|
| 高度 | 统一 300px（含标题区）；大图 360px |
| 结构 | 标题 + 右上角时间粒度切换（今日/7日/30日/学期）+ 图表 + 图例 |
| 数量 | **一屏 3–5 个**，超出放 Tab |
| 空数据 | 显示"暂无数据"插图 + 说明，不显示空坐标轴 |
| 加载 | 骨架块，高度与图表一致，避免跳版 |

**ECharts 全局配置约定**：

```js
// 配色：8 色循环，首色为品牌蓝
color: ['#1677FF','#0FA968','#FF8F1F','#7C4DFF','#00B5C4','#E5484D','#8C8C94','#F5A623']
// 通用
grid: { left: 48, right: 24, top: 32, bottom: 32 }
axisLine:  { lineStyle: { color: '#E5E7EB' } }
axisLabel: { color: '#9A9AA4', fontSize: 12 }
splitLine: { lineStyle: { color: '#F0F0F4', type: 'dashed' } }
tooltip:   { trigger: 'axis', backgroundColor: 'rgba(31,31,38,.9)', textStyle:{ color:'#fff', fontSize:12 } }
```

- 折线/面积：`smooth:false`（数据要精确，不做平滑）；面积图透明度 0.12
- 柱状：柱宽 ≤ 24px，圆角 `[4,4,0,0]`
- 饼/环：环形，内径 60%，中心显示总计
- 纵轴**从 0 起**；若数据差异过大用对数轴并在图注说明
- 时间轴标签：日粒度 `MM-DD`，月粒度 `YYYY-MM`

### 4.3 表格

| 项 | 规范 |
|---|---|
| 行高 | 48px（紧凑 40px 用于纯查看页） |
| 表头 | `--f-sm` 500，`--text-2`，底色 `#FAFAFB`，吸顶 |
| 正文 | `--f-sm`，`--text-1`；次要列 `--text-2` |
| 数值列 | 右对齐 + `tabular-nums` |
| 状态列 | 用 Tag（见 4.4），不用纯文字 |
| 操作列 | 右固定，最多 3 个文字按钮，超出收进「更多」下拉 |
| 选择 | 首列复选框，选中后顶部出现批量操作条 |
| 分页 | 右下，`showSizeChanger`，默认 20 条 |
| 空态 | 插图 + 文案 + 重置筛选按钮 |

### 4.4 Tag（状态）

| 状态 | 底色 | 文字 |
|---|---|---|
| 待审核 | `#FFF7E6` | `--st-pending` |
| 已通过 / 正常 | `#E8F8F0` | `--st-pass` |
| 已拒绝 / 异常 | `#FDECEC` | `--st-fail` |
| 已下架 / 停用 | `#F2F3F5` | `--st-off` |
| 进行中 | `#E6F0FF` | `--brand` |

Tag 统一：字号 12px，圆角 4px，左右 padding 8px，不带点状指示器（避免视觉噪音）。

### 4.5 筛选栏

- 卡片顶部或表格上方一行：输入框 + 2–4 个下拉/日期范围 + 右侧「查询 / 重置」
- 超过 4 个条件时收起为「展开筛选」，展开后仍保持一行两列
- 日期范围提供快捷项：今日 / 近 7 日 / 近 30 日 / 本学期

### 4.6 抽屉 / 模态

- 详情查看用 **Drawer**（右侧 640px 或全屏 60%），不打断上下文
- 表单编辑用 **Modal**（宽 640px），破坏性操作用 `Modal.confirm` 并标红主按钮
- 所有 Modal 的确定按钮在右、取消在左

### A2 看板信息层级（严格按此顺序）


## 六、交互与动效

| 场景 | 时长 | 说明 |
|---|---|---|
| 菜单折叠 | 200ms | — |
| 表格 hover 行 | 底色 `#FAFAFB`，无过渡 | 管理端不做位移/阴影 |
| Drawer 滑入 | 250ms | ease-out |
| 图表渲染 | 500ms 动画 | ECharts 默认，不要关闭（有"数据出来了"的反馈价值） |
| 全局上限 | ≤400ms | — |

**反馈规则**：所有写操作后必须出现 `message` 提示（成功绿、失败红）；批量操作显示进度与结果汇总；删除类操作 Toast 带「撤销」（5s 内）。

## 七、无障碍与文案

- 正文对比度 ≥ 4.5:1；状态色**不得单独表意**，必须配文字（「待审核」三个字不能省）
- 图表必须提供数据表切换（「查看数据」→ 表格），兼顾色弱用户与数据核对需求
- 表格支持键盘方向键导航；所有操作按钮可 Tab 聚焦
- 文案：管理端用中性、明确的书面语（「确认下架该商品？」），不用口语（「聊一聊」）
- 金额 `¥1,234.00`，百分比保留 1 位小数，日期 `YYYY-MM-DD HH:mm`

## 八、落地约定

```
src/
├─ design/tokens.css        ← 三端共用 Primitive + 本端 Semantic
├─ components/
│   ├─ StatCard/            ← KPI 卡
│   ├─ ChartCard/           ← 图表卡（统一的 loading / empty / 时间粒度切换）
│   ├─ FilterBar/           ← 筛选栏
│   ├─ StatusTag/           ← 状态标签（映射唯一）
│   └─ TableToolbar/        ← 批量操作条
├─ charts/                  ← ECharts 配置（统一 theme.js）
├─ views/admin/             ← A1–A9
└─ router/
```

- **禁止写死色值**，一律 `var(--*)`
- 图表配色集中在 `charts/theme.js` 注册为 ECharts 主题，禁止各页面单独写 color
- UI 库建议：**Ant Design Vue**（与本文档视觉语言一致）或 Element Plus；两者都需覆盖主色为 `#1677FF`
- 与用户端共用同一前端工程（Vue3 + Vite），按角色分流路由：用户端 `/`，管理端 `/admin`

## 九、与另两端的关系

| 层 | 关系 |
|---|---|
| Primitive Token | ✅ 三端共用 |
| Semantic 主色 | 🔶 管理端用蓝 `#1677FF`。与用户端的暖色刻意区分——角色不同（管理 vs 消费），场景不同（查 vs 逛），这是合理的**角色化色彩策略**，不是不一致 |
| 状态色 | ✅ 全端共用（待审核/通过/拒绝/停用的四色映射在小程序与用户端同样适用） |
| 成色评级 A–D | ✅ 全端共用，文案与颜色一一对应，由后台统一管理 |
| 布局导航 | ❌ 独立（左菜单 + 内容区） |
| 数据可视化 | ❌ 本端专属；用户端只保留极轻图表，小程序端仅一个趋势图 |
| 响应式 | ❌ 仅适配 ≥1280，不做移动端——管理端的使用者坐在办公桌前 |
