# notes/16 · 失物招领模块实现笔记（示例业务）

> 示例业务笔记：本文以校园「失物招领」为题，演示业务实现笔记的写法。失物招领不是 campus-market 已实现的功能，文中的表名、接口与配置均为示例，不对应本项目任何代码。原「图片上传、字典校验与询单留言」三功能的设计决策已摘存至 notes/18 问题 3，代码不受本文影响。

失物招领是练习业务笔记的好样本：它和二手交易同为「用户产生内容、陌生人凭内容建立联系」的形态，但状态机更短、权限模型更严——拾到的东西不属于平台，招领单是信息而非货品。这就让「哪些能力可以照搬、哪些必须重新决策」在每一章都成为真问题。本文按实现顺序说三件事：拾物照片怎么传、物品字典怎么校验、失主与拾主怎么联系，最后是配置与遗留。

## 拾物照片：多图上传的票据制

**结论：招领单的图片交互与闲置发布同构——选图、换票、上传、提交 objectKey 列表，四步不变；变的是业务下限与隐私口径。**

同构的底气来自票据层：前端不直接猜后端允许哪种传法，先调发票接口换一张票据，票据里带 `mode` 与对应的上传参数（PROXY 给服务端接口地址，DIRECT 给存储的 PUT 签名 URL），前端按 mode 分流，但整个交互流程只有一种。模式切换是后端一个配置项的事，前端零改动——招领模块复用同一套上传通道时不需要为此付任何前端成本，这是票据制相对「前端自己判断传法」的核心收益。两条通道共同前置校验：扩展名与 MIME 双重白名单、大小上限，且都不信任客户端声明的类型——PROXY 分支拿到文件后仍然过一遍校验，DIRECT 分支的签名 URL 里也带上 `Content-Type` 限制，签名只对约定类型生效。

业务差异落在两处。其一是**数量下限**：拾物照要求「全景加细节特写」至少两张，发布闲置不设下限——下限放服务端校验，前端只做格式与大小的预检，少一次往返。其二是**删除时的对象清理**：招领单关闭或误删撤销时，图片清理必须挂在事务边界上，先在事务内查出未删除的图片，把真正的删除动作注册到 `afterCommit`。顺序不能反——先删对象再回滚，等于单子还在而照片没了，这比留下孤儿对象更坏。

本章真正的决策点是读路径。二手场景把 bucket 设为公开读、URL 直拼不过期是划算的，省掉每次查询批量签名的开销；但招领照片里会出现学生证、票据、钥匙——**同一个上传能力，读路径的取舍由业务数据敏感度决定，不由技术偏好决定**。招领场景要么把默认改成私有读加签名 GET，要么至少在拾取登记时提示「请对证件信息打码」，二者取一，不能默认继承公开读。

## 物品字典：类别与场所的两级校验

**结论：分级校验在招领场景同样是必须的，理由与二手场景同构——停用一个类别，不该让引用它的历史招领单永远无法编辑。**

发布招领单要校验的引用从闲置的四件套（分类、成色、校区、面交点）换成三件套：物品类别、拾取场所、校区；成色换成物品状态（完好、破损），仍按 `code` 匹配且统一转大写后比对，与描述必填规则的大写归一口径保持一致。选填项对应「认领地点」，传了才查。真正容易错的是校验口径的严度：如果编辑时也要求「类别必须启用」，那么任何一个被停用类别下的历史招领单都将永远无法编辑，保存任何字段都被拒。所以校验收成两个口径——**发布（含暂存）查存在且启用，走启用缓存零额外 IO；编辑只查存在**，编辑是低频操作，几条计数查询的代价可以忽略。

缓存因此也必须分两套 key：招领单可引用已停用或改过名字的类别，只缓存启用项会让历史招领单的类别解析成空。管理端要看到全量（含停用项）用于维护，用户端只下发启用项——两套 key 不能合并，合并等于让历史数据在用户端失真。

## 失物联系：同步留言与隐私边界

**结论：「内容加双方」的唯一键模型直接迁移——招领单加拾主失主天然落进同一会话；权限判定换一道，隐私要求升一级。**

复用留言结构而不新建表，关键在于原有的会话表本就按「内容实体加双方」建模：招领场景里 `user_a`/`user_b` 仍按 id 大小序归一，拾主发布、失主认领，双方天然落进同一行。并发首聊用撞唯一键兜底——`DuplicateKeyException` 时取回对方刚建的那一行，不报错、不建重。发送权限换一道判定：发布场景是「买家发起时对方必须是卖家」，招领场景是「认领人须已登录、且招领单仍在待认领态」；**回复方不限这条不变**——能在会话里回复的，对方必然是在该招领单下认领过的人，由会话存在性天然约束，不需要额外权限代码。

同步模式的心智模型照搬：进会话轮询、拉取即已读，消息只做游标分页向上翻，已读标记独立，未读数一次批量查只取会话 id 一列、在内存侧计数。差别在内容本身——二手留言里交换的是价格与面交地点，全量直出没有问题；招领留言里会交换联系方式与证件细节，**脱敏从可选变成必需**：手机号中间四位打码、证件号只显末四位，这类规则要放在输出的唯一出口上做，不能指望每个调用方自觉。

## 配置与遗留

招领模块不新增配置项：上传模式、存储开关与二手场景共用同一组，配置的价值就在于切换时不动前端。遗留三项：孤儿对象无定时巡检（误删与回滚都会留下，二期补）；认领超时（如三十天）自动关闭未做；留言敏感信息脱敏未做，当前是全量直出。
