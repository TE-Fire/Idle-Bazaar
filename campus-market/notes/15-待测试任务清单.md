## 使用方式

每项含优先级、覆盖范围、验收标准。P0 不通过不准交付；P1 是主链路回归；P2 是稳健性与边界。用例按「给定时 → 操作时 → 期望」写，可直接照做。

## P0 · 核心正确性

### T1 · pay 两级占位并发（notes/13 缺口 #1）

- **覆盖**：`POST /api/order/{id}/pay`；Redis Lua 前置 + MySQL 条件更新兜底。
- **验收标准**：
  1. 两个请求同时 pay 同一在售商品 → 恰好一个成功（订单 `待面交(2)`），另一个报 2005 商品已被买走。
  2. 成功方商品 `status = 已售出(5)` 且 `version + 1`；同商品其余待付款订单全部转 `已取消(5)`、`cancel_type = 被占用`。
  3. 同一订单重复 pay → 第二次直接放行成功，不重复占位、不重复取消兄弟订单。
  4. 删掉 `cm:item:state:{itemId}` 后再 pay → 走 DB 裁决，结果仍正确（缓存缺失不放行误拒）。

### T2 · 纠纷发起与裁决闭环（本轮新增）

- **覆盖**：`POST /api/order/{id}/dispute`、`refund` 拒绝自动建单、`/api/appeal`(bizType=3) 收紧、`POST /admin/review/appeal/{appealId}/judge`。
- **验收标准**：
  1. `待面交(2) / 已验货(3) / 退款中(6)` 订单，任一方发起 → 订单转 `纠纷中(8)` 冻结；`appeal` 新增一条 `biz_type=3`、`status=待复审(1)`、`applicant=发起人`、`biz_id=订单 id`；管理端审核队列立即可见该单。
  2. 卖家拒绝退款 → 订单 `纠纷中(8)`，appeal 申请人 = **买家**，理由含卖家拒绝原因。
  3. `待付款(1) / 已取消(5) / 已完成(4) / 已退款(7) / 纠纷中(8)` 订单再发起 → 2003 拒绝；非当事人发起 → 2004。
  4. 对非纠纷中订单直接 `POST /api/appeal`(bizType=3) → 2003 拒绝；同一订单提交第二条申诉 → 申诉不允许。
  5. 裁决买家赢 → 订单 `已退款(7)` **且商品恢复在售(3)**（恢复后可被再次下单支付）；裁决卖家赢 → 订单 `已完成(4)`。
  6. 裁决后订单不可再发起纠纷 / 取消 / 退款（终态拦截）。

### T3 · 退款恢复商品在售（本轮新增，notes/13 O9 数据变化）

- **覆盖**：`refund` 同意、`autoRefund`（24h 系统自动）、`settleDispute → 已退款(7)` 三路。
- **验收标准**：
  1. 三路任一发生 → `item.status` 由 `已售出(5)` 恢复 `在售(3)`。
  2. Redis `cm:item:state:{itemId}` 重置为 `ON_SALE`（不是残留的永久 `SOLD`）；恢复后的商品可被新买家走完下单 → 支付。
  3. 退款期间商品若已被平台强制下架(7) → 不被抢回在售（条件更新限定 SOLD）。

### T4 · 审核未过修改后重提（本轮新增，business/01 状态机）

- **覆盖**：`POST /api/item/{id}/edit`；前端「我的商品 → 审核未过 → 编辑 → 保存」。
- **验收标准**：
  1. 审核未过(6) 商品编辑保存 → 商品回 `待审核(2)`，`item_audit` 新进行列，管理端队列可见；**不论是否改价格 / 成色**（区别于已发布商品的免审口径）。
  2. 驳回商品改成色 D + 空描述 → 仍被 1000 拦（D 档规则两条路都查）。
  3. `待审核(2) / 已售出(5) / 已强制下架(7)` 编辑仍报 1109；非卖家编辑报 1108。

### T5 · 均价缓存失效（本轮新增）

- **覆盖**：`receive`、`settleDispute → 已完成(4)` 后 DEL `cm:item:catAvg`。
- **验收标准**：
  1. 订单完成后立即再触发一次均价查询 → 缓存未命中、直查库（连打两次可见值刷新）。
  2. Redis 故障时 `evict` 失败不抛错，功能降级只多滞后一个 TTL。

## P1 · 主链路回归（订单前端接入后执行）

- **T6 交易全链路**（notes/13 §5.1 九项）：发布送审 → 审核通过 → 下单 → 支付 → 核销 → 收货；分支覆盖取消（付款前 / 后）、退款申请与受理、纠纷发起与裁决。Web 与 mini 双端各跑一遍。
- **T7 登录与鉴权**：验证码一次性（先比对后删除）、60 秒节流、未注册 4015、封禁 4001；token 7 天；401 时清 token 跳登录并带 redirect。
- **T8 我的商品操作矩阵**：草稿（续编辑 / 送审 / 删除）、在售（编辑 / 下架）、已下架（编辑 / 删除）、审核未过（编辑 / 删除）、已强制下架（不可删）。
- **T9 审核队列**：进队四快照分量（`report_count` 实查、`image_risk` 恒 0、`credit_deduct`、`price_abnormal`）、五项权重排序、SLA 标记。

## P2 · 稳健性与边界

- **T10 字典与缓存**：停用字典项不影响历史商品名称解析；`cm:dict:all` 与 `cm:dict:admin:full` 两套 key 行为不变；catAvg 读写异常降级直查库。
- **T11 操作日志**：成功记录走 `afterCommit`（回滚即丢弃）、失败记录立即提交（notes/12 四路径）；异步落库 ≤1 秒可见。
- **T12 越权**：非本人商品 / 订单一律 1108 / 2004；详情页已强制下架报 1101（不泄露商品存在性）。
- **T13 软删一致性**：`item` 与 `item_image` 一并写 `deleted`；学生端与管理端删除口径一致（已强制下架不可删）。
