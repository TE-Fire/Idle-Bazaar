## 一、模块定位

**字典是全端一致性的源头：五份基础数据由后台下发，Web 端、小程序、管理端都不得本地硬编码。**

F-A7 判据原文：

> 这四张字典是**全端一致性的源头**，必须由后台下发，三端不得本地硬编码。

这句话决定了本模块的两个业务属性：

| 属性 | 含义 | 业务后果 |
|---|---|---|
| **源头** | 其余模块全部通过 id 引用字典（商品的 `category_id`、用户的 `college_id`、面交的 `meet_point_id`） | 字典改名或停用，引用处一起变，不需要三端发版 |
| **低频、高风险** | 改一次，三端的展示、筛选、报表全跟着变 | 写权限收敛到**超级管理员一人**；运营要用字典，只能读下拉，不进这一页 |

### 1.1 五份字典与它们的下游

| 字典 | 内容 | 谁在消费 |
|---|---|---|
| 校区 `dict_campus` | 2 个校区 | 学院与面交点的归属、用户所属校区、报表拆行 |
| 学院 `dict_college` | 12 个学院 | 用户认证信息、报表「学院 × 品类」矩阵的**行** |
| 商品分类 `dict_category` | 8 个一级 + 二级（共 23 条） | 发布商品、审核判读、搜索筛选、报表列 |
| 成色 `dict_grade` | A–D 四档（文案 + 色值） | 发布、商品详情徽章、报表成色分布 |
| 面交点 `dict_meet_point` | 6 个校内点位 | 下单选面交点、报表「面交所热力」 |

引用链（**校区是唯一的链顶**，学院与面交点都挂在它下面）：

```
dict_campus ──┬─→ dict_college.campus_id
              └─→ dict_meet_point.campus_id

dict_category ──→ item.category_id ──→ 发布 / 审核 / 筛选 / 报表
dict_grade    ──→ item.grade       ──→ 详情徽章 / 报表成色分布
```

> `business/03` F-A7 把「学院 / 校区」合成一条列，页面上它们是两个 Tab——不影响业务，只是条目粒度不同。

**本模块没有「删除」业务。** 五份字典一律**停用**（`status` 1 启用 / 0 停用），不做物理删除——

## 三、业务流程详述

### D1 · 商品分类维护（两级树）

**业务目标**：维护商品分类的**两级树**，作为发布、审核判读、搜索筛选、报表列的统一口径。

**触发方与入口**：超级管理员 → A7 内容管理 → 「分类」Tab。
分类以**平铺列表 + `parentId`** 的形式下发，树由前端组装（不是后端返回嵌套结构）。

**前置条件**：无。分类即使为空，平台仍能运行——只是发布页没有可选项。

**主流程**

| 步 | 动作 | 说明 |
|---|---|---|
| 1 | 查看两级树 | 一级与二级同行展示，二级标注所属一级 |
| 2 | 新增一级分类 | 名称 + 图标 + 排序 → 落库时 `parent_id = 0` |
| 3 | 新增二级分类 | 在某一级行上点「新增子分类」，上级固定为该一级 |
| 4 | 编辑分类 | 改名 / 改图标 / 改排序 / 改上级 |
| 5 | 启停分类 | 停用一级 → **连带停用它的全部二级**；启用**不**连带 |

**数据与状态变化**

| 操作 | `dict_category` 的变化 |
|---|---|
| 新增 | 插一行，`status=1`，`sort` 取用户输入 |
| 编辑 | 只更新提交的字段 |
| 停用一级 | 该行 `status=0`，并**批量**把 `parent_id = 该 id` 的行一起置 0 |
| 启用一级 | 只把该行置 1，二级**保持停用**，需要单独启用 |

**异常与边界分支**

| 场景 | 处理 |
|---|---|
| 新增二级时，父级不存在 / 已停用 / 本身是二级 | 拒绝（6003「上级分类本身不是一级分类」）——树只允许两级，禁止三级 |
| 同级重名 | 拒绝（6002） |
| 名称空、超 32 字 | 参数错误（1000） |
| 编辑时把上级设成**自己** | ⚠️ 当前**未拦截**，见 §七 已知缺口 |

**约束与规则**

- 一级分类的 `parent_id` 在库里存 **0**（不是 NULL）；请求里「不传」与「传 `"0"`」同义
- **只允许两级**：一级父级必须为 0，二级父级必须是一个**启用的一级**
- **编辑分类只校验同级不重名**，不重复校验父级合法性——前端「上级分类」下拉只列一级且排除自己，后端不再写第二遍
- 排序统一 `ORDER BY sort, id`
- 停用一级连带二级，是为了避免出现「父已停用、子仍可选」的半成品状态

**涉及**：页面 A7 分类 Tab ｜ 表 `dict_category` ｜ 权限 `content.edit` ｜ 错误码 1000 / 6002 / 6003

### D2 · 成色等级维护（A–D 四档）

**业务目标**：维护商品成色的**文案与徽章色值**，供三端共用；前端不得写死文案或颜色，改色值不需要前端发版。

**触发方与入口**：超级管理员 → A7 内容管理 → 「成色」Tab。

**前置条件**：无——成色按 `code` **upsert**，空库直接调也能补出四条。

**主流程**

| 步 | 动作 | 说明 |
|---|---|---|
| 1 | 查看四档 | A / B / C / D，显示文案与色块 |
| 2 | 编辑一档 | 改文案 / 改色值；`code` 由路径带入 |
| 3 | 启停一档 | 停用后该档不再随字典下发（发布页不可选） |

**数据与状态变化**

| 操作 | `dict_grade` 的变化 |
|---|---|
| 保存 | 按 `code` 找行：有则更新，无则插入（upsert） |
| 色值留空 | 取默认 `#8E8E93`（iOS 灰），不会渲染出透明徽章 |
| 停用 | `status=0`；`/api/dict/all` 只下发启用项，因此停用档不再出现在选择框里 |

**异常与边界分支**

| 场景 | 处理 |
|---|---|
| `code` 不在 A/B/C/D | 拒绝——成色是固定四档，没有「新增一档」这回事（页面上也没有「新增」按钮，`code` 选择框置灰） |
| 色值格式不是 `#RRGGBB` | 参数错误（1000）；**表单「没填」必须发 `null` 而不是空串**——正则只跳过 null，不跳过空串 |
| `code` 缺失 | 参数错误（1000）「成色编码不能为空」 |

**约束与规则**

- `code` 是**业务主键**（A–D 是真数据），不是路由代理键，所以它留在请求体里；但**以路径上的 `{code}` 为准**
- 色值取 `char(7)` 定长（`#RRGGBB` 正好 7 个字符）——定长本身就是一层校验
- 成色文案与色值的唯一出处是这张表；`design/02` 与前端 mock 都只是它的副本
- 唯一键是 `uk_code(code, deleted)`，**带 `deleted`**——已删除的 code 可以再用（本项目不做物理删除，这条实际不会触发）

**涉及**：页面 A7 成色 Tab ｜ 表 `dict_grade` ｜ 权限 `content.edit` ｜ 错误码 1000

### D3 · 面交点维护

**业务目标**：维护校内**面交点**（食堂、图书馆、宿舍区、校门等），供下单时选择、供报表统计「哪个点过载」。

**触发方与入口**：超级管理员 → A7 内容管理 → 「面交点」Tab。

**前置条件**：所属校区必须已存在且启用。

**主流程**

| 步 | 动作 | 说明 |
|---|---|---|
| 1 | 查看列表 | 每行显示名称 + 所属校区（冗余下发 `campusName`）+ 开放时段 + 启停 |
| 2 | 新增 | 名称 + 所属校区 + 开放时段 |
| 3 | 编辑 | 改名 / 改校区 / 改时段 |
| 4 | 启停 | 停用后不再出现在下单选择框里 |

**异常与边界分支**

| 场景 | 处理 |
|---|---|
| 所属校区不存在 / 已停用 | 拒绝——不能把面交点挂到一个停用的校区下 |
| 同一校区下重名 | 拒绝 |
| 名称空 | 参数错误（1000） |

**约束与规则**

- 面交点必须归属一个校区（`campus_id` 非 0），这是它和学院的区别
- 开放时段可空（`open_hours`），仅作展示，不参与下单校验
- 列表带 `campusName` 冗余字段，前端不为每行再查一次校区表

**涉及**：页面 A7 面交点 Tab ｜ 表 `dict_meet_point` ｜ 权限 `content.edit` ｜ 错误码 1000

### D4 · 学院维护

**业务目标**：维护学院列表，用于用户认证信息与报表「学院 × 品类」矩阵的行维度。

**触发方与入口**：超级管理员 → A7 内容管理 → 「学院」Tab。

**前置条件**：无。学院**可以**不指定校区。

**主流程**

| 步 | 动作 | 说明 |
|---|---|---|
| 1 | 查看列表 | 名称 + 所属校区（可为「未指定」） |
| 2 | 新增 / 编辑 | 名称 + 所属校区（可空） |
| 3 | 启停 | 停用后不再出现在用户认证与筛选下拉里 |

**异常与边界分支**

| 场景 | 处理 |
|---|---|
| 同级重名 | 拒绝 |
| 名称空 | 参数错误（1000） |
| 不选校区 | 允许——落库 `campus_id = 0`，下发时转成「未指定」 |

**约束与规则**

- **`campus_id` 可以缺省**（与面交点相反）。口径与分类的「一级存 0」同一套路：库里存 0，接口层转空，交给前端显示「未指定」
- 报表按校区拆行时，未指定校区的学院归入「未指定」一组

**涉及**：页面 A7 学院 Tab ｜ 表 `dict_college` ｜ 权限 `content.edit` ｜ 错误码 1000

### D5 · 校区维护

**业务目标**：维护校区列表，它是**引用链的顶端**——学院与面交点都挂在它下面。

**触发方与入口**：超级管理员 → A7 内容管理 → 「校区」Tab。

**前置条件**：无。

**主流程**

| 步 | 动作 | 说明 |
|---|---|---|
| 1 | 查看列表 | 校区名 + 启停 |
| 2 | 新增 / 编辑 | 名称 |
| 3 | 启停 | 停用 → **连带停用**该校区下的**面交点与学院**；启用**不**连带 |

**异常与边界分支**

| 场景 | 处理 |
|---|---|
| 同级（校区之间）重名 | 拒绝 |
| 名称空 | 参数错误（1000） |

**约束与规则**

- 停用校区**连带**停用它下面的学院与面交点，理由与分类相同：校区是链顶，让下级挂在一个停用校区下没有业务意义
- 启用校区**不**连带启用下级（与分类一致，避免"悄悄放开一堆"）
- 连带由**后端一条 SQL** 完成，前端不做——前端漏发一次就会数据不一致

**涉及**：页面 A7 校区 Tab ｜ 表 `dict_campus`、`dict_college`、`dict_meet_point` ｜ 权限 `content.edit` ｜ 错误码 1000

### D6 · 字典只读下发（三端共用）

**业务目标**：把五张字典的**启用项**一次性下发给三端，让 Web 端发布页、小程序、管理端筛选下拉拿到同一份数据。

**触发方与入口**：Web 端 / 小程序 / 管理端页面调用 `GET /api/dict/all`。

**前置条件**：无需登录（学生端以后要调，走 `/api/**` 而不是 `/admin/**`）。

**主流程**

| 步 | 动作 | 说明 |
|---|---|---|
| 1 | 取缓存 | 先读 Redis `cm:dict:all` |
| 2 | 命中 | 直接返回 |
| 3 | 未命中 | 查五张表的启用项 → 组装 → 写缓存（TTL 60s）→ 返回 |

**异常与边界分支**

| 场景 | 处理 |
|---|---|
| Redis 读失败 | **降级直查库**——字典是发布页的依赖项，Redis 抖一下不能让整个发布页 500 |
| Redis 写失败 | 只记 warn 日志，不影响本次返回 |

**约束与规则**

- **只下发启用项**（`status=1`），停用项不出现在这里——这正是「停用」的业务含义：**不能再被选**，但历史引用不受影响
- **两套缓存、两个 key，语义不同**。学生端 `/api/dict/all` 缓存**启用项**（`cm:dict:all`）；管理端 `/admin/dict/**` 与商品/审核列表回填走 `cm:dict:admin:full`，缓存**含停用项的全量**——停用项仍可能被历史商品引用，缺了它名称会解析成 null。写操作统一 `evictCache()` 把两个 key 一并 DEL（`afterCommit`），故管理端改完字典仍即时可见，不会出现「改完列表没变」。
- 缓存失效策略是**删除**而不是更新：写了就 DEL，下次读自然重建（读多写少）；DEL 幂等，没有并发乱序问题
- 事务提交后才删缓存（`afterCommit`）——回滚时库没变，缓存里的旧值本来就正确，不需要补偿

**涉及**：接口 `GET /api/dict/all` ｜ 缓存 key `cm:dict:all` ｜ 免登录

## 四、通用业务规则

### 4.1 停用，而不是删除

五张表都有两个"状态"字段，业务上只用前者：

| 字段 | 含义 | 业务用法 |
|---|---|---|
| `status` | 1 启用 / 0 停用 | **业务开关**。停用 = 不再出现在选择框/下拉，历史引用照常显示 |
| `deleted` | 删除时间戳（0 = 未删） | 技术字段，本模块**不提供删除入口** |

### 4.2 排序与唯一性

| 规则 | 依据 |
|---|---|
| 一律 `ORDER BY sort, id` | 五张表都有 `sort`，索引建成 `(status, sort)` |
| 同级不重名 | 新增/编辑时校验 |
| 成色 `code` 全局唯一 | `uk_code(code, deleted)` |

### 4.3 级联停用（只有"停用"这一侧，启用不连带）

| 停用对象 | 连带停用 | 不连带 |
|---|---|---|
| 一级分类 | 它的全部二级分类 | 启用一级时，二级保持停用 |
| 校区 | 该校区下的面交点 + 学院 | 启用校区时，下级保持停用 |

## 五、业务关系与状态一览

```
用户（超级管理员，content.edit）
  │
  ├─ D1 分类维护 ──→ dict_category（两级，parent_id 自关联）
  │                     └─ 停用一级 → 连带二级
  ├─ D2 成色维护 ──→ dict_grade（code A–D，含 color）
  ├─ D3 面交点维护 ─→ dict_meet_point（必挂校区）
  ├─ D4 学院维护 ──→ dict_college（校区可空）
  └─ D5 校区维护 ──→ dict_campus
                        └─ 停用 → 连带面交点 + 学院

        ↓ 后端合成一份「启用项」

  D6 GET /api/dict/all（免登录，60s 缓存）
        ↓
  Web 端发布页 · 小程序 · 管理端筛选下拉
```

### A.3 已存在的库如何补列

改 `schema.sql` **对已建好的库不生效**（只在首次初始化时执行）。本机踩过：`color` 只加在
`schema.sql` 里，实际库没有这一列，`/api/dict/all` 直接 5000（`Unknown column 'color'`）。
补列 SQL：

```sql
ALTER TABLE dict_grade ADD COLUMN color char(7) NOT NULL DEFAULT '#8E8E93'
  COMMENT '徽章色值，如 #34C759；后台下发，前端不硬编码' AFTER name;
UPDATE dict_grade SET color = '#1D9E75' WHERE code = 'A';
UPDATE dict_grade SET color = '#34C759' WHERE code = 'B';
UPDATE dict_grade SET color = '#FF9F0A' WHERE code = 'C';
UPDATE dict_grade SET color = '#8E8E93' WHERE code = 'D';

ALTER TABLE dict_college ADD COLUMN campus_id bigint NOT NULL DEFAULT 0
  COMMENT '所属校区，0=未指定', ADD KEY idx_campus (campus_id, status);
```

### A.4 种子数据在哪

`schema.sql` 内联（2 校区 / 12 学院 / 23 分类 / 6 面交点 / 4 成色），
`zz-demo-data.sql` 里 **0 条** dict\_\* 行——**不要**再往那里补字典。
`db/` 目录整个挂进 `/docker-entrypoint-initdb.d/`，按**文件名顺序**执行，数字前缀排在 `schema.sql` 之前，
那时表还没建，脚本会报错打挂初始化（entrypoint 带 `set -e`）。

## 附录 B · 校验规则与错误码

| 场景 | 规则 / 错误码 |
|---|---|
| 新增分类 | 名称非空且 ≤32；父级必须存在、启用、**且自身是一级**（禁止三级）；同级不重名 |
| 编辑分类 | 只校验同级不重名 → 6002 |
| 「一级」「未指定」怎么表示 | 库里存 **0**；不传与传 `"0"` 同义，Service 开头统一转 0 |
| 停用分类 / 校区 | 连带停用下级；启用不连带 |
| 成色 upsert | `code` ∈ A/B/C/D；`color` 空取 `#8E8E93` |
| 新增面交点 | `campusId` 必须存在且启用；同校区不重名 |
| 新增学院 / 校区 | 名称非空、同层不重名；学院可挂「未指定校区」 |
| 删除 | **一律不提供** |

| 错误码 | 含义 |
|---|---|
| 1000 | 参数错误（`@NotBlank` / `@Pattern` 等声明式校验，由 `GlobalExceptionHandler` 统一返回） |
| 6001 | 分类不存在 |
| 6002 | 同级名称重复 |
| 6003 | 上级分类本身不是一级分类 |

## 附录 C · 决策记录

> 原「开工前待拍板的 3 个问题」，已全部拍板并落地。保留编号供代码注释引用。

### 问题 1：`dict_grade` 缺 `color` 列

**决策：给表加 `color`，随字典下发。** 取 `char(7)` 定长，默认 `#8E8E93`。
理由是表注释明确写着「前端不得硬编码文案与颜色」，前端按 code 映射色值会违反这条判据，
而且论文里会被问「为什么颜色改不了」。
顺带修掉了种子文案整体错位一档的问题（A 原叫「几乎全新」）。见附录 A.3。

### 问题 2：`DictCategoryVO.itemCount` 要不要返回

**决策：先不返回真实值**（保留字段、恒为 0），等商品模块落地后再决定换成真值还是删字段。
商品模块现已落地，字段仍为 0，属遗留项（§七）。

### 问题 3：接口路径与权限

**决策**：管理端维护走 `/admin/dict/**`（权限 `content.edit`）；只读下发走 `/api/dict/all`（免登录）。
不把只读下发塞进 admin-api——`/api/**` 归学生端模块，学生端单独部署时不用拖着管理端代码。
`content.edit` 已从运营角色移除（2026-09-30），改的是**角色授权**不是权限点本身，后端注解不用动。

### 问题 4：`dict_college` 缺 `campus_id`

**决策**：照 `dict_meet_point` 同构补列；口径 `0 = 未指定`（与分类一级存 0 一致）。
种子 12 个学院已按主校区(1001) / 东校区(1002) 分配。见附录 A.3。

### 补充：编辑分类为何不校验父级（2026-10-04）

`updateCategory` 只做「同级不重名」一项校验，不调用 `requireParent`。理由是被移除的约束
要么与前端重复（前端只列一级、且提示「有子分类不能挂走」），要么触发场景极窄。
**唯一遗留是「上级不能是自己」两边都没拦**，已在 §七 记为已知缺口。
