## 一、模块定位

**字典是全端一致性的源头：五份基础数据由后台下发，Web 端、小程序、管理端都不得本地硬编码。**

F-A7 判据原文：

> 这四张字典是**全端一致性的源头**，必须由后台下发，三端不得本地硬编码。

这句话决定了本模块的两个业务属性：

| 属性 | 含义 | 业务后果 |
|---|---|---|
| **源头** | 其余模块全部通过 id 引用字典（商品的 `category_id`、用户的 `college_id`、面交的 `meet_point_id`） | 字典改名或停用，引用处一起变，不需要三端发版 |
| **低频、高风险** | 改一次，三端的展示、筛选、报表全跟着变 | 写权限收敛到**超级管理员一人**；运营要用字典，只能读下拉，不进这一页 |

### 1.1 五份字典与它们的下游

| 字典 | 内容 | 谁在消费 |
|---|---|---|
| 校区 `dict_campus` | 2 个校区 | 学院与面交点的归属、用户所属校区、报表拆行 |
| 学院 `dict_college` | 12 个学院 | 用户认证信息、报表「学院 × 品类」矩阵的**行** |
| 商品分类 `dict_category` | 8 个一级 + 二级（共 23 条） | 发布商品、审核判读、搜索筛选、报表列 |
| 成色 `dict_grade` | A–D 四档（文案 + 色值） | 发布、商品详情徽章、报表成色分布 |
| 面交点 `dict_meet_point` | 6 个校内点位 | 下单选面交点、报表「面交所热力」 |

引用链（**校区是唯一的链顶**，学院与面交点都挂在它下面）：

```
dict_campus ──┬─→ dict_college.campus_id
              └─→ dict_meet_point.campus_id

dict_category ──→ item.category_id ──→ 发布 / 审核 / 筛选 / 报表
dict_grade    ──→ item.grade       ──→ 详情徽章 / 报表成色分布
```

> `business/03` F-A7 把「学院 / 校区」合成一条列，页面上它们是两个 Tab——不影响业务，只是条目粒度不同。

## 三、业务条目

### D1 · 商品分类维护（两级树）

**接口**

| 方法 | 路径 | 权限点 | 作用 |
|---|---|---|---|
| GET | `/admin/dict/categories` | `content.edit` | 分类两级平铺列表（含停用项） |
| POST | `/admin/dict/category` | `content.edit` | 新增分类 |
| PUT | `/admin/dict/category/{id}` | `content.edit` | 改名 / 改图标 / 改排序 / 改上级 |
| POST | `/admin/dict/category/{id}/status` | `content.edit` | 启停（停用一级连带子级） |

**前置**

- 无。分类即使为空，平台仍能运行——只是发布页没有可选项。

**规则**

1. 查看分类：后端下发**平铺列表**（每行带 `parentId`），树由前端组装；后端不返回嵌套结构。
2. 新增一级分类：提交名称、图标、排序；落库时 `parent_id = 0`。
   1. 名称为空或超 32 字 → 参数错误(1000)
   2. 同级已存在同名分类 → 同级名称重复(6002)
3. 新增二级分类：在某一级行上发起，上级固定为该一级。
   1. 上级不存在、已停用，或上级本身是二级 → 上级分类本身不是一级分类(6003)——树只允许两级，禁止三级
4. 编辑分类：改名 / 改图标 / 改排序 / 改上级。
   1. 同级重名 → 同级名称重复(6002)
   2. **只校验同级不重名**，不重复校验父级合法性——前端「上级分类」下拉只列一级且排除自己，后端不再写第二遍
5. 启用一级分类：只置该行 `status = 启用(1)`，其二级分类**保持停用**，需单独启用。
6. 停用一级分类：该行置 `停用(0)`，并**批量**把 `parent_id = 该 id` 的二级一并置 `停用(0)`。
   1. 目的：避免「父已停用、子仍可选」的半成品状态
7. 一律 `ORDER BY sort, id` 排序。

**状态与数据变化**

| 对象 | 变化 |
|---|---|
| `dict_category` | 新增插一行 `status = 启用(1)`、`sort` 取入参；编辑只更新提交字段；停用一级连带批量置 0 二级 |

### D2 · 成色等级维护（A–D 四档）

**接口**

| 方法 | 路径 | 权限点 | 作用 |
|---|---|---|---|
| GET | `/admin/dict/grades` | `content.edit` | 成色 A–D（含 color，含停用项） |
| PUT | `/admin/dict/grade/{code}` | `content.edit` | 新增 / 编辑成色（按 code upsert） |
| POST | `/admin/dict/grade/{code}/status` | `content.edit` | 启停成色 |

**前置**

- 无。成色按 `code` **upsert**，空库直接调也能补出四条。

**规则**

1. 查看四档：A / B / C / D，显示文案与色块。
2. 保存成色（按路径上的 `{code}` 定位）：
   1. `code` 缺失 → 参数错误(1000)「成色编码不能为空」
   2. `code` 不在 A/B/C/D → 拒绝——成色是固定四档，没有「新增一档」这回事（页面上也没有「新增」按钮，`code` 选择框置灰）
   3. 色值格式不是 `#RRGGBB` → 参数错误(1000)；**表单「没填」必须发 `null` 而不是空串**（正则只跳过 null，不跳过空串）
   4. 色值留空 → 取默认 `#8E8E93`（iOS 灰），不会渲染出透明徽章
   5. 通过 → 按 `code` upsert：有则更新，无则插入
3. 停用成色：转 `停用(0)` 后该档不再随字典下发，发布页不可选；转 `启用(1)` 后恢复下发。

**状态与数据变化**

| 对象 | 变化 |
|---|---|
| `dict_grade` | 按 `code` upsert；色值留空回落 `#8E8E93`；停用时 `status = 停用(0)` |

### D3 · 面交点维护

**接口**

| 方法 | 路径 | 权限点 | 作用 |
|---|---|---|---|
| GET | `/admin/dict/meet-points` | `content.edit` | 面交点列表（带冗余 `campusName`） |
| POST | `/admin/dict/meet-point` | `content.edit` | 新增面交点 |
| PUT | `/admin/dict/meet-point/{id}` | `content.edit` | 改名 / 改校区 / 改时段 |
| POST | `/admin/dict/meet-point/{id}/status` | `content.edit` | 启停面交点 |

**前置**

- 所属校区必须已存在且启用。

**规则**

1. 查看列表：每行显示名称 + 所属校区（冗余下发 `campusName`）+ 开放时段 + 启停状态。
   1. 列表带 `campusName` 冗余字段，前端不为每行再查一次校区表。
2. 新增面交点：提交名称、所属校区、开放时段。
   1. 名称空 → 参数错误(1000)
   2. 所属校区不存在或已停用 → 拒绝——不能把面交点挂到一个停用的校区下
   3. 同一校区下已存在同名 → 拒绝
3. 编辑面交点：改名 / 改校区 / 改时段，校验同第 2 步。
4. 启停面交点：转 `停用(0)` 后不再出现在下单选择框里。
5. 开放时段（`open_hours`）可空，仅作展示，不参与下单校验。

**状态与数据变化**

| 对象 | 变化 |
|---|---|
| `dict_meet_point` | 新增 / 编辑；`campus_id` 必须非 0（面交点与学院的关键差别） |

**接口**

| 方法 | 路径 | 权限点 | 作用 |
|---|---|---|---|
| GET | `/admin/dict/colleges` | `content.edit` | 学院列表（带 `campusId` + `campusName`） |
| POST | `/admin/dict/college` | `content.edit` | 新增学院 |

### D5 · 校区维护

**接口**

| 方法 | 路径 | 权限点 | 作用 |
|---|---|---|---|
| GET | `/admin/dict/campuses` | `content.edit` | 校区列表 |
| POST | `/admin/dict/campus` | `content.edit` | 新增校区 |
| PUT | `/admin/dict/campus/{id}` | `content.edit` | 改名 |
| POST | `/admin/dict/campus/{id}/status` | `content.edit` | 启停（停用连带面交点与学院） |

**前置**

- 无。

**规则**

1. 查看列表：校区名 + 启停状态。
2. 新增 / 编辑校区：提交名称。
   1. 名称为空 → 参数错误(1000)
   2. 同级（校区之间）重名 → 拒绝
3. 启用校区：只置该行 `status = 启用(1)`，**不**连带启用下级。
4. 停用校区：该行置 `停用(0)`，并**连带停用**该校区下的**面交点与学院**。
   1. 理由：校区是链顶，让下级挂在一个停用校区下没有业务意义
   2. 连带由**后端一条 SQL** 完成，前端不做——前端漏发一次就会数据不一致

**状态与数据变化**

| 对象 | 变化 |
|---|---|
| `dict_campus` | 停用连带批量置 0：`dict_meet_point` + `dict_college` 中该校区下行 |

### D6 · 字典只读下发（三端共用）

**接口**

| 方法 | 路径 | 权限点 | 作用 |
|---|---|---|---|
| GET | `/api/dict/all` | **免登录** | 五张字典的启用项一次下发，走 Redis |
| GET | `/admin/dict/options` | **只校验登录** | 管理端筛选下拉用的只读下发（`/items` 等四角色共用页面） |

> 第二条不能走字典维护接口：那些接口全部标注 `content.edit`（只有超管有），运营、审核员、只读进来会直接 403。

**前置**

- 无需登录（学生端以后要调，走 `/api/**` 而不是 `/admin/**`）。

**规则**

1. 请求到达 → 先读 Redis。
2. 缓存命中 → 直接返回。
3. 缓存未命中 → 查五张表的**启用项** → 组装 → 写缓存（TTL 60s）→ 返回。
4. Redis 读失败 → **降级直查库**——字典是发布页的依赖项，Redis 抖一下不能让整个发布页 500。
5. Redis 写失败 → 只记 warn 日志，不影响本次返回。
6. 写操作（D1–D5）成功后 → 在**事务提交后**删除缓存（`afterCommit`）：
   1. 两个 key 一并 DEL：`cm:dict:all`（启用项，学生端）与 `cm:dict:admin:full`（含停用项全量，管理端与商品 / 审核列表回填）
   2. 停用项仍可能被历史商品引用，管理端缓存**必须含停用项**，否则名称会解析成 null
   3. 策略是**删除**而不是更新：写了就 DEL，下次读自然重建（读多写少）；DEL 幂等，没有并发乱序问题
   4. 事务提交后才删——回滚时库没变，缓存里的旧值本来就正确，不需要补偿

**状态与数据变化**

| 对象 | 变化 |
|---|---|
| Redis | 读穿 + 写后失效；命中 0 次 DB IO，未命中 5 表查询后写缓存 |

## 四、通用业务规则

### 4.1 停用，而不是删除

五张表都有两个"状态"字段，业务上只用前者：

| 字段 | 含义 | 业务用法 |
|---|---|---|
| `status` | 1 启用 / 0 停用 | **业务开关**。停用 = 不再出现在选择框 / 下拉，历史引用照常显示 |
| `deleted` | 删除时间戳（0 = 未删） | 技术字段，本模块**不提供删除入口** |

### 4.2 排序与唯一性

| 规则 | 依据 |
|---|---|
| 一律 `ORDER BY sort, id` | 五张表都有 `sort`，索引建成 `(status, sort)` |
| 同级不重名 | 新增 / 编辑时校验 |
| 成色 `code` 全局唯一 | `uk_code(code, deleted)`，带 `deleted`——已删除的 code 可以再用（本项目不做物理删除，实际不会触发） |

### 4.3 级联停用（只有"停用"这一侧，启用不连带）

| 停用对象 | 连带停用 | 不连带 |
|---|---|---|
| 一级分类 | 它的全部二级分类 | 启用一级时，二级保持停用 |
| 校区 | 该校区下的面交点 + 学院 | 启用校区时，下级保持停用 |

### 4.4 「一级」「未指定」怎么表示

- 库里存 **0**，不是 NULL；请求里「不传」与「传 `"0"`」同义，Service 开头统一转 0。
- 分类一级的 `parent_id = 0`、学院未指定校区的 `campus_id = 0`，同一套路：库存 0，接口层转空，前端显示「未指定」。
- 面交点相反，`campus_id` **必须非 0**。

### 4.5 三条通用约定

1. 响应一律 `Result<T>`。
2. `Long` 全局序列化成 String（id 精度），前端类型里 id 本来就是 `string`。
3. 新增 / 编辑的 body **不含 `id`**（改哪一条由 URL 路径决定），成色的 `code` 例外（业务主键）；启停接口的 body 只有 `enabled` 一个字段。

## 五、业务关系与验收

```
用户（超级管理员，content.edit）
  │
  ├─ D1 分类维护 ──→ dict_category（两级，parent_id 自关联）
  │                     └─ 停用一级 → 连带二级
  ├─ D2 成色维护 ──→ dict_grade（code A–D，含 color）
  ├─ D3 面交点维护 ─→ dict_meet_point（必须归属校区）
  ├─ D4 学院维护 ──→ dict_college（校区可空）
  └─ D5 校区维护 ──→ dict_campus
                        └─ 停用 → 连带面交点 + 学院

        ↓ 后端合成一份「启用项」

  D6 GET /api/dict/all（免登录，60s 缓存）
        ↓
  Web 端发布页 · 小程序 · 管理端筛选下拉
```

**验收口径**

- [x] 五张 Tab 的数据与库一致（校区 2、学院 12、分类 23、成色 4、面交点 6）
- [x] 改一条字典（改名 / 停用）刷新即生效，无需重启前端
- [x] 成色文案与 `design/02` 一致：A 全新未拆 / B 几乎全新 / C 轻微使用痕迹 / D 明显使用痕迹
- [x] 停用一级分类后，二级一并停用；停用校区后，其下面交点与学院一并停用
- [x] 无 `content.edit` 的角色（审核员、运营、只读）**看不到写按钮**，直接调接口返回 1002，路由跳 `/403`，菜单不出现
- [ ] 停用后的分类不出现在「新增商品可选分类」里（等 C 端发布页落地后验证）

**已知缺口**

| 缺口 | 影响 | 修法（未执行） |
|---|---|---|
| 编辑分类时 `parentId = 自身 id` 未拦截 | 库里会写下 `parent_id = id`，前端组树死循环 | `updateCategory` 加一行 `BizAssert.isTrue(parentIdInDb != id, ...)` |
| `DictCategoryVO.itemCount` 恒为 0 | 接口保留了字段，但商品模块落地前不是真实值 | 商品模块已落地，可回头决定改为真值或删字段 |
| `dict_college.campus_id` 只在 `schema.sql` 里加过 | 已建好的库不会自动补列，需手动 `ALTER` | 见附录 A.3 补列 SQL |

### A.3 已存在的库如何补列

改 `schema.sql` **对已建好的库不生效**（只在首次初始化时执行）。本机踩过：`color` 只加在
`schema.sql` 里，实际库没有这一列，`/api/dict/all` 直接 5000（`Unknown column 'color'`）。
补列 SQL：

```sql
ALTER TABLE dict_grade ADD COLUMN color char(7) NOT NULL DEFAULT '#8E8E93'
  COMMENT '徽章色值，如 #34C759；后台下发，前端不硬编码' AFTER name;
UPDATE dict_grade SET color = '#1D9E75' WHERE code = 'A';
UPDATE dict_grade SET color = '#34C759' WHERE code = 'B';
UPDATE dict_grade SET color = '#FF9F0A' WHERE code = 'C';
UPDATE dict_grade SET color = '#8E8E93' WHERE code = 'D';

ALTER TABLE dict_college ADD COLUMN campus_id bigint NOT NULL DEFAULT 0
  COMMENT '所属校区，0=未指定', ADD KEY idx_campus (campus_id, status);
```

### A.4 种子数据在哪

`schema.sql` 内联（2 校区 / 12 学院 / 23 分类 / 6 面交点 / 4 成色），
`zz-demo-data.sql` 里 **0 条** dict\_\* 行——**不要**再往那里补字典。
`db/` 目录整个挂进 `/docker-entrypoint-initdb.d/`，按**文件名顺序**执行，数字前缀排在 `schema.sql` 之前，
那时表还没建，脚本会报错打挂初始化（entrypoint 带 `set -e`）。

## 附录 B · 校验规则与错误码

| 场景 | 规则 / 错误码 |
|---|---|
| 新增分类 | 名称非空且 ≤32；父级必须存在、启用、**且自身是一级**（禁止三级）；同级不重名 |
| 编辑分类 | 只校验同级不重名 → 6002 |
| 「一级」「未指定」怎么表示 | 库里存 **0**；不传与传 `"0"` 同义，Service 开头统一转 0 |
| 停用分类 / 校区 | 连带停用下级；启用不连带 |
| 成色 upsert | `code` ∈ A/B/C/D；`color` 空取 `#8E8E93` |
| 新增面交点 | `campusId` 必须存在且启用；同校区不重名 |
| 新增学院 / 校区 | 名称非空、同层不重名；学院可归属「未指定校区」 |
| 删除 | **一律不提供** |

| 错误码 | 含义 |
|---|---|
| 1000 | 参数错误（`@NotBlank` / `@Pattern` 等声明式校验，由 `GlobalExceptionHandler` 统一返回） |
| 1002 | 无权限（`@SaCheckPermission` 校验失败，路由跳 `/403`） |
| 6001 | 分类不存在 |
| 6002 | 同级名称重复 |
| 6003 | 上级分类本身不是一级分类 |

## 附录 C · 决策记录

> 原「开工前待拍板的 3 个问题」，已全部拍板并落地。保留编号供代码注释引用。

### 问题 1：`dict_grade` 缺 `color` 列

**决策：给表加 `color`，随字典下发。** 取 `char(7)` 定长，默认 `#8E8E93`。
理由是表注释明确写着「前端不得硬编码文案与颜色」，前端按 code 映射色值会违反这条判据，
而且论文里会被问「为什么颜色改不了」。
顺带修掉了种子文案整体错位一档的问题（A 原叫「几乎全新」）。见附录 A.3。

### 问题 2：`DictCategoryVO.itemCount` 要不要返回

**决策：先不返回真实值**（保留字段、恒为 0），等商品模块落地后再决定换成真值还是删字段。
商品模块现已落地，字段仍为 0，属遗留项（§五）。

### 问题 3：接口路径与权限

**决策**：管理端维护走 `/admin/dict/**`（权限 `content.edit`）；只读下发走 `/api/dict/all`（免登录）。
不把只读下发塞进 admin-api——`/api/**` 归学生端模块，学生端单独部署时不用拖着管理端代码。
`content.edit` 已从运营角色移除（2026-09-30），改的是**角色授权**不是权限点本身，后端注解不用动。

### 问题 4：`dict_college` 缺 `campus_id`

**决策**：照 `dict_meet_point` 同构补列；口径 `0 = 未指定`（与分类一级存 0 一致）。
种子 12 个学院已按主校区(1001) / 东校区(1002) 分配。见附录 A.3。

### 补充：编辑分类为何不校验父级（2026-10-04）

`updateCategory` 只做「同级不重名」一项校验，不调用 `requireParent`。理由是被移除的约束
要么与前端重复（前端只列一级、且提示「有子分类不能挂走」），要么触发场景极窄。
**唯一遗留是「上级不能是自己」两边都没拦**，已在 §五 记为已知缺口。
