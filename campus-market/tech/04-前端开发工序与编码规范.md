# 前端开发工序与编码规范（Vue 3）

> 上游：`business/` 三份业务与流程文档、`prototypes/`（界面依据）、`design/` 三份 UI 规范
> 平行：`tech/02-前端技术选型与工程约定.md`（技术栈）、`tech/01-后端技术选型与工程约定.md`（接口契约）
> 兄弟篇：`tech/03-后端开发工序与编码规范.md`（同一套流水线，工序一一对应）

**定位**：这份是前端那条流水线——从"原型页"到"能跑、能联调、能答辩"的组件，中间每道工序的输入、动作、产出、质检标准。

**用法同 `tech/03`**：当工序卡用，不要通读。每开一个新页面从 F0 走起，DoD 没打勾不进下一道。

---

## 零、流水线总览

```
F0 备料  原型与需求确认   prototypes/xx + business/xx + design/xx  ──► 页面要点卡
   ↓
F1 对色  Token 核对      缺的变量先补 packages/tokens              ──► 零写死色值
   ↓
F2 开模  契约先行         TS 类型 + api 函数 + mock                ──► 可脱离后端跑
   ↓
F3 加工  组件实现         布局 → 组件树 → 交互                      ──► 可运行页面
   ↓
F4 质检  三态与边界自测   加载/空/错误 + 断点 + 权限                 ──► 自测记录
   ↓
F5 包装  提交与评审       分支 + commit + CR 清单                    ──► 合并入 develop
   ↓
F6 出厂  联调与交付       替换 mock 为真接口 + 演示脚本卡             ──► 可答辩页面
```

**铁律**：F2 的 mock 没跑通，F3 不许开始。否则你会一边写 UI 一边等后端，两边都卡。

## 一、F0 备料：原型与需求确认

**输入**：`prototypes/` 对应页 + `business/` 对应流程 + `design/` 对应规范

**标准动作**
1. 打开原型页（如 `prototypes/web/web-publish.html`），把页面上的**每一块**抄成要点：区块名、字段、交互（hover / 拖拽 / 展开）
2. 查 `design/` 对应规范里的硬约束（字阶、阴影使用范围、断点行为、主色）
3. 写出**页面要点卡**（≤10 行）：路由、权限点、涉及接口、状态分支（空/加载/错误/无权限）、校园四项字段是否齐全

**DoD**
- [ ] 知道这个页面的**权限点字符串**（与后端 Sa-Token、原型 `data-perm` 三方同名）
- [ ] 校园四项字段（成色评级 / 校区 / 面交点 / 学号认证）在卡片、筛选、详情三处都列到了
- [ ] 空态、加载态、错误态、无权限态四种都有明确设计
- [ ] 原型里没画出的状态，**先补原型再写代码**，不要自己发明

---

## 二、F1 对色：Token 核对

**标准动作**
1. 页面要用到的每个视觉值，先在 `packages/tokens` 里找对应变量
2. **找不到就补 Token，不许写死色值**——写死一次，暗色主题和跨端一致性就废一次
3. 需要新变量时，先判断是 primitive 层（三端共用：色板/字阶/间距/圆角）还是 semantic 层（本端语义：`--color-primary`）

**DoD**
- [ ] 全文件搜不到 `#` 开头的十六进制色值
- [ ] 全文件搜不到裸的 `px` 字号（必须走 `--f-*`）
- [ ] 阴影的使用符合规范：用户端只在 hover 浮起与对比条两处，管理端卡片默认极浅，**小程序端不用阴影**
- [ ] 主色用的是**本端主色**（用户端黄 / 管理端蓝 / 小程序橙），不是"顺手统一"

---

## 三、F2 开模：契约先行

**标准动作**
1. 从后端 Knife4j（OpenAPI 3）生成 TS 类型到 `packages/api`
2. 写业务 api 函数（按域分文件：`api/item.ts`、`api/order.ts`…）
3. **写 mock**（`vite-plugin-mock` 或 MSW），数据形态与后端契约一致，包含各状态样本
4. 页面先用 mock 跑通——这一步之后，后端接口什么时候好都不影响你

**DoD**
- [ ] 所有 ID 字段类型是 `string`（雪花 ID，`number` 会精度丢失）
- [ ] 金额是字符串或按分计的整数，**不做浮点运算**
- [ ] mock 覆盖了各种状态（待审核 / 已售出 / 已驳回 / 已下架），不是只有一条成功数据
- [ ] api 函数返回的是解包后的 `data`，业务层不认识 `Result` 包装

## 四、F3 加工：组件实现

### 4.1 组件分层

| 层 | 放什么 | 例子 |
|---|---|---|
| 基础组件 | 无业务语义、可复用 | `AppButton`、`AppEmpty`、`AppImage` |
| 业务组件 | 含业务语义、跨页复用 | `ItemCard`、`GradeTag`、`MeetPointTag` |
| 页面组件 | 路由直接挂载，不复用 | `pages/item/Detail.vue` |

**商品卡是典型**：列表页、搜索页、详情页推荐、发布页预览**四处复用**，必须是同一个业务组件，不许复制四份。

### 4.2 组件写法

- 一律 `<script setup lang="ts">`
- props 用 `defineProps<Props>()` 类型化；双向绑定用 `defineModel()`；事件用 `defineEmits<{...}>()`
- **单文件超过 200 行就拆**——拆的是子组件或 composable，不是加注释分区
- 复杂逻辑抽 `useXxx.ts`（`useItemFilter`、`useChatSocket`），组件里只留模板与胶水代码
- 页面文件顶部写 10 行内注释：对应哪个原型页、对应业务文档哪条流程

### 4.3 目录结构

```
apps/web/src/
├─ api/          接口函数（按域）
├─ assets/       静态资源
├─ components/   基础组件
├─ business/     业务组件（ItemCard 等）
├─ composables/  useXxx
├─ layouts/      框架布局（侧栏 / 顶栏 / TabBar）
├─ pages/        路由页面
├─ router/       路由与守卫
├─ stores/       Pinia
├─ styles/       Token 引入 + 少量全局
├─ types/        本地类型补充
└─ utils/        纯函数工具
```

### 4.4 状态管理边界

| 放 Pinia | 不放 Pinia |
|---|---|
| 登录态与用户信息 | 页面内的筛选条件（`ref` 即可） |
| 字典（分类/成色/面交点/学院/校区） | 列表数据与分页（放组件，避免售出状态不刷新） |
| 未读消息数 | 表单值（用 UI 库表单） |
| 全局 UI 偏好（视图模式、密度） | 弹窗开关 |

**禁止把业务列表持久化到 localStorage**——缓存的列表会显示已售出的商品。

### 4.5 路由

- 页面级路由懒加载（`() => import(...)`）
- 路由 meta 带 `title` / `perm`（权限点）/ `keepAlive`
- 守卫两级：登录态 → 权限点；无权限跳 403，**不要静默跳首页**（用户会以为系统坏了）
- 管理端只做 ≥1280，不做移动端适配；用户端必须过四个断点

### 4.6 样式

- 组件样式一律 `scoped`；覆盖 UI 库样式用 `:deep()` 并注明原因
- 禁用 `!important`（唯一例外：覆盖 UI 库内联样式，且必须写注释）
- 命名用语义 class（`.item-card`），不用 `.mt-8` 这类原子类（理由见 `tech/02` 第九章）
- 用户端断点：375–767 / 768–1023 / 1024–1439（4 列 + 常驻侧栏 240px）/ ≥1440（锁 1280）

### 4.7 请求与交互

- 组件里**不许直接 import axios**，统一走 `api/` 层
- 页面切换用 `AbortController` 取消在途请求，否则瀑布流快速翻页会结果乱序
- 提交按钮必须 loading + 防重复点击
- 错误提示要用户可读，并把 `traceId` 放进控制台或提示末尾（联调用）

## 五、F4 质检：三态与边界自测

**每个页面至少过这 8 条**

1. 加载态（骨架屏 / loading，不是白屏）
2. **空态**（无数据，有引导文案）
3. 错误态（接口 500，可重试）
4. 无权限态（切到只读角色看是否按 `data-perm` 隐藏）
5. 超长文本（标题两行截断，不撑破卡片）
6. 图片加载失败（占位图，不是破图）
7. 断点（用户端四个宽度逐一过，管理端 1280 与 1920）
8. 键盘可达（Tab 能走到主要操作，Enter 能提交）

**DoD**
- [ ] 8 条全过
- [ ] 与原型页逐块对比，视觉一致（不一致先改原型再改代码，保持原型是唯一依据）
- [ ] 控制台无报错、无 Vue 警告（尤其是 key 与 prop 类型）
- [ ] 网络面板里没有重复请求、没有 4xx

## 六、F5 包装：提交与评审

**分支**：`main`（可演示）/ `develop` / `feature/xxx` / `fix/xxx`
**提交信息**：`类型(端-模块): 简述`，如 `feat(web-item): 发布页拖拽多图与实时预览`

**CR 检查清单**

| # | 检查项 |
|---|---|
| 1 | 有没有写死色值或裸 px 字号 |
| 2 | ID 是不是 `string` 类型（不是 number） |
| 3 | 金额有没有用浮点运算 |
| 4 | 有没有 `any` |
| 5 | 组件有没有超过 200 行 |
| 6 | 业务组件有没有被复制多份（应抽到 `business/`） |
| 7 | 列表有没有空态与错误态（只写了有数据的样子） |
| 8 | 提交按钮有没有 loading 防重复 |
| 9 | 权限点字符串与后端、原型是否三方一致 |
| 10 | 有没有把业务列表持久化到 localStorage |
| 11 | 用户端四个断点是否都过了 |
| 12 | 请求有没有走 `api/` 层（组件里没有裸 axios） |
| 13 | 路由有没有懒加载 |
| 14 | 控制台有无警告 |
| 15 | 文件头注释有没有写"对应哪个原型页" |

## 七、F6 出厂：联调与交付

- mock 切真接口时，**只改 `api/` 层的 baseURL 与 mock 开关**，业务代码不动——这是 F2 契约先行换来的
- 每个演示场景写一张**脚本卡**（几步、点哪里、看到什么），答辩照着走
- 截图留档：每个页面至少一张，用于论文"系统实现"章节
- 三端对齐复查：同一商品在 Web / 小程序 / 管理端的显示是否遵循"校园四项字段三处可见"

## 八、反模式清单（见到即打回）

| 反模式 | 为什么是错的 |
|---|---|
| 组件里写死 `#FFD100` | 换主题、跨端复用全废 |
| ID 用 `number` | 雪花 ID 超过 2^53，精度丢失，尾数变 00 |
| 商品卡复制四份 | 改一处要改四处，必然漏 |
| 只在有数据时调页面 | 空态/错误态是答辩时最容易被试出来的状态 |
| 静默跳首页代替 403 | 用户以为系统坏了；权限演示也失去意义 |
| 把列表存 localStorage | 显示已售出商品，状态机失效 |
| 瀑布流不做懒加载/取消 | 快速翻页结果乱序，图片撑爆内存 |
| 组件里直接 axios | baseURL、拦截器、错误处理全都绕过去了 |
| 先写 UI 再等接口 | 后端一改，UI 白写；mock 先行可完全避免 |
| 用 `any` 糊类型 | 联调时的类型错误会变成运行时崩溃 |
