## 一、本端定位：桌面是「发布 + 比价」的端

学生在 Web 端做的事和手机上不是同一件。**Web 端不负责"逛"，负责"出"和"选"。**

| 桌面能、手机不能 | 说明 | 对应业务 |
|---|---|---|
| 批量发布 | 拖拽多图 + 排序 + 右侧实时预览 + 键盘提交 | W-B4 |
| 多对象对比 | 最多 4 件横评参数 | W-B3 |
| 常驻筛选 + 悬停预览 | 一次看到全部筛选条件与组合结果 | W-B1 |
| 双视图（网格/列表） | 看图选网格，比参数选列表 | W-B1 |

**明确不做的事（划清边界，别把 Web 做成万能端）**：

- ❌ 不做线下场景：面交导航、当面验货、扫码签收归移动端
- ❌ 不做即时沟通的主战场：Web 聊天是辅助（打字方便时），核心 IM 在移动端
- ❌ 不做真实支付：全端统一为「模拟支付 + 线下交付」（个人主体申请不到微信支付商户资质）

## 三、核心业务流程

### F-W1 · 找货（检索闭环）

```
进入首页
 ├─ 分类条选类目 ──────────┐
 ├─ 顶栏搜索关键词 ────────┤
 └─ 直接浏览推荐 ──────────┤
                          ▼
              左侧常驻筛选（可叠加）
              分类树 / 价格区间 / 成色 A-D（复选）/ 校区 / 仅看认证卖家 / 发布时间
                          ▼
              已选条件在顶部以 chip 回显（可单个删除 / 一键清空）
                          ▼
              工具条：共 N 件 · 排序（默认/价格/时间/热度）· 网格⇄列表
                          ▼
              浏览结果 → 悬停看第二张图 → 进详情（F-W2）
```

**判据**
- 桌面一屏至少 12 件，宁挤不空（`design/01` 原则 3）
- 筛选是"与"逻辑（AND），成色多选取"或"（OR）——这是例外，需在 UI 上写清「成色任选其一」
- 结果为空时给「放宽条件的建议」（去掉校区 / 扩大价格区间），不要只显示"暂无数据"

### F-W2 · 比价决策（对比闭环）★桌面独占

```
浏览中把商品加入对比（卡片 hover 浮出「＋对比」）
   → 选中 ≥1 件时底部对比条滑入（56px，4 槽位）
   → 已选 2–4 件时可点「开始对比」
   → 进入 P4 对比页：参数横评表
        对比维度：价格 / 原价 / 成色 / 校区 / 面交点 / 卖家信用等级 / 发布时间 / 商品标签
        （议价不是独立业务，不进入对比维度）
        （差异项高亮，相同项弱化）
   → 决策：下单 / 收藏 / 移除某件 / 继续加
```

**判据**
- 上限 4 件：超过 4 件人的短时记忆比较不过来
- **只允许同类目对比**：跨类目（教材 vs 相机）参数无可比性，点第 2 件时若类目不同，提示「对比需同一分类」而非静默失败
- 对比条可收起但不清空选择（用 checkbox 控制显隐），收起后角标显示已选数量
- 卖家本人不能对比自己的商品
- 已售出/已下架的商品在对比条中被标灰，不占用槽位计数

### F-W3 · 批量发布 ★本端最大价值

```
进入 /publish
 ① 图片区：拖拽 / 点击选择，≤9 张
      - 拖拽进入时整块区域高亮（dashed 黄边）
      - 首张默认为主图，可拖拽改序、可删
      - 上传中显示进度；失败单张重试，不影响其他
 ② 智能填充：上传后可给「分类猜测 / 成色建议」，由用户确认，不自动写死
 ③ 表单区：标题 / 分类 / 成色 A-D / 价格 + 原价 / 校区 / 面交点 / 描述 / 是否可议价 / 是否包配送
 ④ 右侧实时预览：按 P1 卡片与 P2 详情页的真实版式渲染（所见即所得）
 ⑤ 提交：
      - Ctrl+Enter 或点「发布」
      - 前端校验：9 图以内、标题 5–50 字、价格 > 0、必填项齐全
      - 提交后 → 商品进入「待审核」→ 跳结果页（预计 X 小时内完成审核 + 「再发一件」）
 ⑥ 暂存草稿：离开页面时若已填内容，提示保存草稿（本地 + 云端）
```

**判据**
- 提交即送审，**不直接上架**（校园实名制下，先审后发是平台信任机制的一部分）
- 重新编辑已发布商品：改图/改价/改描述 → 若改动价格或成色，回「待审核」；只改描述可免审
- 发布页是 Web 端唯一"必须做"的页面——不做，本端就没有存在理由（`design/01` 第五章）

### F-W4 · 交易推进

```
P2 详情页点「我想要」
 → 确认订单：面交点（下拉，默认卖家常用点）+ 面交时间（默认 3 天内）+ 备注
 → 提交 → 订单「待付款」（**商品不锁定，先付款先得**）
 → 模拟支付（本平台不走真实资金流，点「确认付款」即完成）
 → 订单「待面交」，双方可见面交点与时间
 → 线下见面（这一步发生在手机端/线下，Web 只做状态展示与备注补充）
 → 买家确认收货 → 订单「已完成」→ 触发互评（F-W5 评价）
```

**判据**
- 待付款超时 **30 分钟**自动取消（校园交易节奏快，超时不宜过长）
- **无预定机制**：付款前商品仍在售、可被他人拍下；付款成功才转「已售出」，其余待付款订单自动取消并通知。以付款为唯一占位判据
- 议价**不是独立业务**：聊天里口头问价即可，订单金额一律按标价成交
- 订单一旦「待面交」，取消需双方确认；单方取消记一次违约（影响信用分）
- Web 端不做"面交导航/扫码签收"，页面只提示「请在移动端查看导航与扫码」

### F-W5 · 售后与纠纷

```
已完成前发现问题
 → 买家「申请退款」（待付款 / 待面交阶段均可）
     ├─ 卖家同意 → 直接取消/退款，无违规记录
     ├─ 卖家 24h 未响应 → 系统自动同意
     └─ 卖家拒绝 → 进入「纠纷中」→ 转管理端 E 流程介入
 → 交易后发现问题（货不对板）→ 举报商品/卖家（转管理端 F 流程）
 → 对处置结果不服 → 申诉（转管理端 F4 复审）
```

**判据**
- 纠纷一旦进入，订单冻结，双方均不能再操作，直到裁决
- Web 端只提供"发起 + 查看进度 + 补充凭证"，裁决权全在管理端

## 四、本端可见的状态

### 商品（卖家视角）

| 状态 | 含义 | 本端可做 |
|---|---|---|
| 草稿 | 未提交 | 继续编辑 / 删除 |
| 待审核 | 已提交 | 只能看，不能改关键字段 |
| 在售 | 审核通过 | 编辑 / 下架 / 置顶（若开放） |
| ~~已预定~~ | **该状态已取消**（无预定机制） | 拍下不锁货，付款才占位 |
| 已售出 | 交易完成 | 查看订单 / 评价 |
| 已下架 | 卖家主动下架 | 重新上架 / 编辑 |
| 审核未过 | 驳回 | 看驳回原因 → 修改后重提 |
| 已强制下架 | 平台处置 | 申诉 |

### 订单

```
待付款 ──30min超时──> 已取消
   │
   └─付款─> 待面交 ──双方确认取消──> 已取消
              │        └─已付款后取消─> 退款中 ─> 已退款
              └─确认收货─> 已完成 ─> 互评
              └─任一方发起─> 纠纷中（冻结，转管理端）
```

订单终态：`已完成` / `已取消` / `已退款` / `纠纷已裁决`。

## 五、桌面独占能力清单（论文可用）

1. 常驻左侧筛选栏（240px）+ 已选条件 chip 回显——移动端只能收进抽屉
2. 悬停态：卡片上浮、切换第二张图、浮出「＋对比」
3. 最多 4 件参数横评
4. 网格 ⇄ 列表双视图
5. 批量发布：拖拽多图 + 排序 + 实时预览 + `Ctrl+Enter` 提交
6. 双栏消息（会话列表 + 对话区同屏）

> 论文句式参考：*主流二手平台的 Web 端多为移动端附属品（闲鱼网页版支付仍需回 App 扫码），桌面的原生能力未被兑现。本设计将 Web 端定位为"发布与比价端"，用上述六项能力兑现其独立价值。*

### 已决策的三项未决问题（2026-09-26）

| 问题 | 决策 | 落地方式 |
|---|---|---|
| 议价是否作为独立业务 | **不作为** | 「可议价」降级为商品展示标签（卖家勾选），口头议价发生在聊天里；不做报价/还价流程与状态，订单金额一律按标价成交；对比维度与筛选条件均不出现议价 |
| 是否需要预定机制 | **不需要** | 取消商品「已预定」状态。拍下生成待付款订单（30 分钟超时取消），付款前商品不锁定、先付款先得；付款成功才转「已售出」，其余待付款订单自动取消并通知 |
| 是否开放置顶 / 推广 | **不做** | 商品管理只保留编辑 / 下架 / 删除；排序靠校区、成色、时间、信用权重，不引入商业化曝光位 |
