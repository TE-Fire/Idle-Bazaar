# 校园二手交易平台 · 现有产品与设计参考

> 调研日期：2026-09-26
> 用途：毕设选题「校园二手交易平台」定方向前的竞品与设计参考梳理
> 配套：
> - `参考设计board.html` —— 移动端 4 个方向 + 管理端 3 个方向的骨架示意
> - `用户端Web版board.html` —— 用户端 Web 版 4 个方向 + 响应式断点 + 三端 Token 统一策略

## 一、先看结论：你要做的东西，其实有两种完全不同的产品人格

现有二手平台基本分成两极，**选哪一边决定了后面所有的视觉决策**：

| | **A. 社交流 / 兴趣圈层** | **B. 专业流 / 确定性交易** |
|---|---|---|
| 代表 | 闲鱼（鱼塘）、Depop、Carousell | 转转（严选验机）、Vinted、OfferUp |
| 用户来的动机 | 逛、被种草、找到同好 | 明确要买 / 卖某一件东西 |
| 首页是什么 | 关注流、话题、推荐瀑布流 | 分类金刚区 + 搜索 + 精准推荐 |
| 视觉策略 | 强风格、图片优先、留白少 | 克制度高、信息清晰、可信感 |
| 校园适配度 | ★★★★★ 学生来二手市场的动机大量是"逛" | ★★★☆☆ 缺少信任机制会劝退 |

**判断**：针对年轻群体 + 校园场景，建议走 **A（社交流）为主、B 的关键机制做补充**。因为校园场景最强的先天优势是**熟人半熟人信任**（同一所学校、学号认证），这天然支撑"逛"的动机；但必须在关键环节补上 B 的确定性：学号实名、校内面交点、成色评级。

### 2.1 国内主流（必须看的三个）

**闲鱼 vs 转转的一个值得注意的反差点**：多篇竞品分析都提到，闲鱼用黄色高亮关键元素、反差强、"一贯性"好；而转转把各种功能图标做成五颜六色，反而稀释了主色、显得凌乱。**这是可以直接写进论文的一条：主色只用于关键元素，不要给每个功能图标不同颜色。**

## 三、用户端选什么：微信小程序 vs App

这是你的待决问题。站在**毕设**的角度给判断：

| 维度 | 微信小程序 | 原生 App / uni-app |
|---|---|---|
| 答辩说服力 | 中（评委见得太多，容易做流水） | 高（若真做出来并打包上架/提供安装包） |
| 开发成本 | 低，微信云开发可一把梭（登录/支付/数据库） | 中高，uni-app / React Native 可跨端，但要处理发布、适配 |
| 支付 | 微信支付需商户资质，**个人主体难以申请** | 同样卡在支付，毕设常用做法是"模拟支付/线下交付" |
| 登录 | `wx.login` 一键获取，天然适配校园场景（学生用微信） | 需自己实现，还要处理短信/第三方登录 |
| 校园传真实名 | 可结合微信 + 学号/校园邮箱二次认证 | 同上，实现成本略高 |
| 演示体验 | 评委手机扫码即可，**展示门槛最低** | 需要安装 APK / TestFlight，稍麻烦 |

**建议（基于"年轻群体 + 校园 + 毕设"三个前提）**：

> **主体做微信小程序，但用 uni-app（或 Taro）写同一套代码，同时能编译成 H5 和一个 APK 端。**
> 这样答辩时可以三端同屏演示（小程序扫码 + 网页展示 + 安卓包），且论文里能写成"基于 uni-app 的多端一致性方案"，比只做小程序或只做一个假 App 都扎实。

如果时间紧、追求稳妥：**就做微信小程序 + Web 管理端**，这是绝大多数同类型毕设的标准配置，风险最低。

## 四、补：用户端再做一个 Web 端，值得吗？

> 配套可视化：`用户端Web版board.html`

**结论：值得，而且这可能是你比同类毕设多出来的那半档分。** 但要立住一个前提——**Web 端必须是"独立设计的一端"，不能是"手机屏幕拉宽版"**。

### 4.1 先说三个真实理由

| 理由 | 说明 |
|---|---|
| **发布场景天然属于桌面** | 卖闲置最痛苦的一步是「拍照之外的填信息」：写描述、标成色、定价格、传 5 张图。手机端打字慢、切图麻烦。桌面端拖拽批量传图 + 右侧实时预览 + 键盘操作，是真实的效率差。毕业季一次性出 20 本书，只有桌面扛得住 |
| **逛的场景属于手机，比价的场景属于桌面** | 学生买二手数码/教材时会开 4 个页面横评参数。手机做这件事成本极高。这就是 Web 端存在的独立价值 |
| **答辩演示门槛最低** | 小程序要扫码、App 要装包，Web 端评委直接点开就能看。三端同屏时，Web 端是信息量最大、最容易被看清的那一端 |

### 4.2 现有产品的 Web 端都在什么水平

| 产品 | Web 端状态 | 能借鉴 / 要避开的点 |
|---|---|---|
| **闲鱼网页版**（goofish.com） | 真实存在且可用：分类导航 + 重点品类 + 兴趣频道三段式，商品沿用移动端"上文下图"，靠大屏做同屏多列；<strong>但支付环节仍需扫码回到 App 完成</strong> | 借鉴：大屏做同屏多列。避开：交易闭环断裂——你的毕设要做到「Web 端能独立走完全流程」，这就是超越点 |
| **eBay** | 桌面端最强：左侧常驻筛选栏（分类树/价格区间/成色/所在地）+ 网格⇄列表双视图 + 对比功能 | 直接抄骨架。这套交互是二手电商二十年收敛出来的最优解 |
| **Vinted / Depop** | 官网基本是移动端的响应式放大，桌面体验一般，留白浪费严重 | 反面教材：说明「把移动端拉宽」这条路走不通 |
| **Grailed** | 编辑排版风：大图 + 衬线标题 + 极度克制，把二手服饰做出了杂志感 | 学"气质"。若你主打教材/胶片相机/乐器这类有故事的品类，这条路的记忆点最强 |
| **多抓鱼** | 米白纸感、留白极大、统一成色评级，靠克制建立质感 | 学"品类纪律"：统一成色评级免去沟通成本，这条比任何视觉都值钱 |

**一条可以直接写进论文的观察**：
> 主流二手平台的 Web 端普遍是移动端的附属品（闲鱼网页版支付需回 App 扫码），桌面端的原生能力——常驻筛选、悬停预览、多对象对比、批量发布——基本没有被兑现。本设计将 Web 端作为独立端进行设计，而非响应式适配。

### 4.3 Web 端必须做出来的五件事（否则就没必要做）

1. **常驻左侧筛选栏**（240px）：分类树 + 价格双滑杆 + 成色复选 + 校区。已选条件在顶部用可删除 chip 回显。
2. **悬停态**：`:hover` 卡片上浮 2–4px，浮出「收藏 / 加入对比 / 问卖家」；图片区 hover 切第二张图。
3. **多对象对比**：最多 4 件，底部升起对比条，进入参数对比页（价格 / 成色 / 校区 / 卖家信用 / 发布时间）。
4. **网格 ⇄ 列表双视图**：网格看图、列表看参数。
5. **批量发布**：拖拽多图 + 右侧实时预览 + `Ctrl+Enter` 提交。

### 4.4 响应式断点（只改列数与侧栏形态，内容结构不动）

| 视口 | 列数 | 筛选器形态 |
|---|---|---|
| 375–767 | 1–2 列瀑布流 | 底部抽屉 |
| 768–1023 | 3 列 | 顶部横向 chips |
| 1024–1439 | 4 列 + 常驻侧栏 | **左侧常驻（关键差异）** |
| ≥1440 | 5–6 列 + 常驻侧栏 | 左侧常驻；内容区锁 1280–1440px 居中，不要拉满 |

> 内容区超过 1600px 后每行字数失控、可读性反而下降，记得锁最大宽度。

### 4.5 三端怎么统一：一套 Token，三套布局

| 层 | 共用度 | 说明 |
|---|---|---|
| Design Token | ✅ 完全共用 | 色板、字阶（1.25 模数）、间距（4pt）、圆角、阴影、成色语义色 |
| 基础组件 | ✅ 共用 90% | Button / Input / Tag / Avatar / Price / ConditionBadge，仅尺寸分 sm（移动）/ md（Web）/ compact（后台） |
| 业务组件 | 🔶 部分共用 | 商品卡共用逻辑，三套模板：移动瀑布卡 / Web 网格卡 / 后台表格行 |
| 布局与导航 | ❌ 各自独立 | 移动底部 Tab / Web 顶栏 + 左筛选 / 后台左菜单 + 内容区 |
| 数据可视化 | ❌ 后台专属 | 用户端只保留极轻图表（我的闲置浏览趋势） |

### 4.6 三端方向已全部确定（2026-09-26 决策）

| 端 | 形态 | 方向 | 主色 | 设计基准文档 |
|---|---|---|---|---|
| **用户 Web 端** | 桌面网页 | **W1 大屏网格电商型**（闲鱼网页版 / eBay） | 黄 `#FFD100`（配黑字） | `design/01-Web用户端-UI设计规范.md` |
| **用户移动端** | **微信小程序**（uni-app） | **A 社区信息流型**（闲鱼 / 转转 / Carousell） | 橙 `#FF6A00`（配白字） | `design/02-移动端小程序-UI设计规范.md` |
| **管理后台** | 桌面网页 | **Y 分析台 Light Card**（Ant Design Pro 风） | 蓝 `#1677FF` | `design/03-管理端Web-UI设计规范.md` |

**三份设计文档是后续写前端代码的唯一视觉依据**，各自包含：Design Token（Primitive + Semantic 两层）、布局栅格与断点、组件规范、页面清单与优先级、交互动效时长、无障碍与文案、目录落地约定、与另两端的共用/差异说明。

**关于三个主色不统一的说明**（可直接写进论文）：这不是不一致，而是**角色化色彩策略**。三者同属高饱和暖色/工具色家族：
- 用户端（黄 / 橙）面向消费者，暖色促进浏览与决策；
- 管理端（蓝）面向运营，冷色降低情绪唤醒、利于长时间数据判读；
- 用户端两档差异源于**控件尺寸**：黄底必须配黑字（对比度 12:1），在小程序 44pt 以下的小控件上可读性下降，故移动端取深一档的橙配白字。
- 真正需要严格统一的是：Primitive 色板、成色评级 A–D、状态色语义、价格与时间格式——这四项已在三份文档中强制对齐。

### 4.7 方向已定：W1 · 闲鱼网页版路线（2026-09-26 决策）

用户选定 **W1 大屏网格电商型（对标闲鱼网页版 goofish.com / eBay）**。原型在 `prototypes/web/web-home.html` 与 `prototypes/web/web-detail.html`。

**"闲鱼那样"拆解成可执行的设计参数**：

| 维度 | 取值 | 理由 |
|---|---|---|
| 主色 | 闲鱼黄 `#FFD100`（仅用于发布按钮、选中态、标签高亮） | 呼应 2.1 那条结论：**主色只给关键元素**，不给每个功能图标不同颜色 |
| 价格色 | 橙红 `#FF5000`（与主色分离） | 价格是决策关键，需要独立于品牌色抢夺注意力 |
| 底色 / 卡片 | 页面 `#F5F5F6`，卡片纯白 | 白卡片 + 浅灰底的"浮起感"，是电商网格的标准解法 |
| 分隔 | 1px `#E8E8EC`，不用阴影堆层级 | 闲鱼网页版几乎不用阴影，靠分割线和留白分层 |
| 圆角 | 卡片 8px、按钮 6px、标签 4px | 小圆角 = 工具感、信息密度高 |
| 卡片结构 | 图在上（4:3）→ 标题（2 行截断）→ 价格 → 成色/校区元信息 | 视觉流一致，扫读成本最低 |
| 信息密度 | 桌面 4 列，一屏 12 件 | 闲鱼网页版的核心优势就是"大屏同屏多陈列" |

**与闲鱼网页版拉开差距的三点**（否则就是抄）：
1. **交易闭环不断**——闲鱼网页版支付要扫码回 App，本设计 Web 端可独立走完下单到确认
2. **多对象对比**——桌面独占能力，闲鱼网页版没有
3. **校园结构化字段**——校区、学号认证、校内面交点，作为独立筛选项与卡片元信息

### 4.7 对技术选型的影响（重要）

**建议把「用户 Web 端」和「管理后台」放进同一个前端工程**，而不是拆成两个项目：

```
campus-web/                 ← Vue 3 + Vite + TS + Tailwind（或 Element Plus / Ant Design Vue）
  ├─ src/views/user/        ← 用户 Web 端：首页 / 商品详情 / 发布 / 对比 / 我的
  ├─ src/views/admin/       ← 管理后台：看板 / 审核 / 用户管理 / 商品管理
  ├─ src/design/tokens.css  ← 三端共用的 Design Token（CSS 变量）
  └─ src/components/        ← 共用基础组件
```

好处：① 一套登录与权限体系（按角色分流路由）② 共用组件库与 Token，开发量省三分之一 ③ 论文里能写成 **「基于同一设计系统的双角色前端架构」**，比"各做一个站"高一级。

**注意区分**：用户 Web 端 ≠ 管理后台。两者权限、信息架构、视觉取向完全不同——用户端重"逛"（大图、留白、风格），管理端重"查"（密度、表格、图表）。共用的是 Token 和基础组件，不是页面。

如果用户端移动端用 uni-app，那 Web 端有两种做法：
- **A（推荐）**：uni-app 的 H5 编译产物只作为"移动端网页版"；桌面 Web 端用上面的 Vue 工程单独写
- **B（省事但有损）**：uni-app 直接编译 H5 当 Web 端用 —— 会是手机版布局拉宽，恰好是 4.2 里批评的做法，不建议

## 五、管理端数据可视化该看什么

管理端不用追求美观，要追求**"一眼看出发生了什么"**。信息层级按这个顺序排：

```
① 今日核心指标（4 个 KPI + 同比/环比）          ← 最上面，最大的数
② 趋势（折线/面积，默认近 7 日、可切 30 日）      ← 第二眼，判断走向
③ 构成（饼/环/堆叠柱：品类分布、成色分布、学院分布）← 第三眼，判断结构
④ 明细 TOP-N（横向柱：热销品类、活跃学院TOP10）   ← 第四眼，找具体对象
⑤ 待处置队列（举报、审核、申诉）                  ← 运营动作入口，必须有权重排序
⑥ 异常/预警区（异常交易、刷量、价格异常）          ← 校园平台特色，很好做论文加分点
```

**校园场景独有的可视化主题（别人没有，你的亮点）**：
- **学期时间轴对比**：学期初 / 学期末 / 毕业季三个流量峰值，做成年度热力条
- **学院 × 品类热力矩阵**：哪个学院在交易什么（这是纯粹的数据故事）
- **面交所热力图**：校内地图上的热点交易地点（楼栋/宿舍区）
- **校内二手循环率**：一个类低碳/循环经济的指标卡，ESG 角度的出挑点

图表选型不要贪多。**一个看板 3–5 个图表是上限**，超过之后阅读成本陡增。
